## 0. 视角总评 (3 句)

1. **信息架构严重错位 + 同质化挤压**: 5 tab 中 3 个错位 (工坊 = Chat、资产 = demo ontology 集合、数字员工 = webview 跳板),且每一屏顶部 3-4 行 chip/filters,纯视觉噪声占 30% 屏心。
2. **"重复功能入口"是 P0 系统性缺陷,不是单点**: 我数出"新建/极速立项"5 个入口、"业务本体 ↔ 项目中心"重复出现 2 次、"通知"无入口但出现 2 处 icon (顶栏 19 + 任务内铃铛未触达)。
3. **App 是 demo 状态,数据稀薄 → 设计缺陷被放大**: 已启用员工 1、执行中任务 1、本月花费 ¥0.00、阻塞 40 / 待办 182 — 长期空状态 + 空骨架卡片 (业务本体 8 个本体 7 草稿 + 1 已锁定,全是英文 Fourth Coffee/E-Commerce/Banking),让"极简"看起来像"无内容",更刺眼。

## 2. 设计维度评分 (1-5 分, 5 = 完美)

| 维度 | 评分 | 证据 |
|---|---|---|

| **对齐 (左/居中/右)** | **4** | 看板卡片内 "未分配" 左对齐 + "16h ago" 右对齐合理;弹层中央 chip "对话/工作" 居中合理。扣分:卡片左缘 4px 状态竖线 + 卡片水平 padding 16px 不一致导致视觉不齐。 |
| **颜色对比 (深色背景文字)** | **3** | 深色背景 + 灰文字 meta (e.g. "16h ago" #6B7280 对比 ~3.5:1,WCAG AA 4.5:1 不达标)。"未分配"灰色字 + 灰色 icon 对比偏低,色弱用户可能识别不出 "未分配" 状态。铃铛红色徽章 19 数字对红色背景白字对比 OK,但 19 字号极小。 |
| **触摸目标 (≥ 44×44 pt)** | **3** | 中央 FAB (~56dp) 达标;底部 tab (5 项 每项 ~64dp width × 80dp height) 达标。但 chip "今日+进行中"/"指派·全部" 等高度约 36-40dp (估),低于 iOS 44pt / MD 48dp 标准,且文字"未分配"左侧 icon 触摸区域过窄。任务卡片整体触摸 OK (约 100dp height),但卡片内"未分配"icon+文字联动区域小,可能误触到卡片打开。 |

**平均分: 3.0 / 5** (中等,有结构性改进空间但非粗糙)

## 4. a11y 评分 (1-5 分, 5 = 全合规)

| 维度 | 评分 | 问题 |
|---|---|---|
| **文字大小可调** | **1** | 没看到字号缩放入口 (顶栏搜索 + 铃铛 + 主区,无设置/无 Aa 字号按钮)。老人/弱视用户无法放大。默认 h1 ~24px 对 50+ 用户偏小。 |
| **对比度 (WCAG AA 4.5:1)** | **3** | 主文字白 ~#F5F5F5 vs #000 背景 >15:1 完美;**灰 meta** (16h ago / 标识 / 标签 / "未分配" 灰色) 估 ~3:1~4:1,边缘达标但不稳。"已锁定" 红字徽章 + 红 dot 在深色背景上对比尚可,但 "已归档 (1)" 红色文字 vs 黑底 在 4128:1 不可达(0.5 lux) 仍合规。 |
| **触摸目标** | **3** | 中央 FAB ~56dp 达标;5 tab ~64×80dp 达标;但 3 chip 横排 (今日+进行中/全部/指派·全部) chip 内 padding ~12dp 加上文字 ~14sp,触摸区 ~36-40dp,低于 48dp 标准。**通知铃铛 touch area 估 ~50×50dp** OK。 |
| **状态语义** | **3** | 顶栏铃铛红点"19" 老人可能看不清 (字号估 10sp) — 字号 + 颜色双编码,但 19 数字字号是关键。紧急熔断红按钮 + 三角警告 icon — "过度刺眼"风险 ([P3] 设计总监 已提同类问题) — 红色按钮在 仪表盘主屏很醒目,符合"警示"目的但与"极简"相悖。 |
| **色盲友好** | **3** | 状态色:已锁定=红、进行中=绿、待审批=灰,红绿色盲用户可能难分辨。任务卡左缘竖线 (白/黄) 是色 + 位置双编码,可接受。看板列头圆点 (待办池=白 / 待处理=黄) 主要靠颜色区分。 |

**a11y 总评: 2.6 / 5** (老人/色盲/字号不可调三处系统性不达标)

## 7. 新发现的 P0 / P1 / P2 (设计 / 交互 / a11y)

### P0 (阻塞使用,必修)

- **P0-1** 5 tab 信息架构严重错位 (波次任务里已记, 但专注当下):
  - 工坊 = Chat (用户说话 vs 创作场)
  - 资产 = 英文 demo 模板 (业务本体 vs 项目中心是混编)
  - 数字员工 = webview 跳板 (出原生 tab)
- **P0-2** "新建" 入口重复 5 处 (重复功能入口)
  - 中央 FAB + 弹层底"极速立项" + 项目中心大卡 + 项目中心悬浮 FAB + 业务本体顶 icon
  - 老板原话 "不能有重复功能入口" 严重违反
- **P0-3** 顶栏通知铃铛 tap 不响应
  - 老人/中文不大点老人会以为 App 坏了

### P1 (体验差)

- **P1-1** 任务 tab 顶部 4 行 chip (状态 + 指派 + 项目 + 排序 + 列表/看板) 占屏 30%, 应屏心撑起
- **P1-2** 任务看板卡片右侧文字被截 (看不全) (截图证据: screen-22-renwu-list.png)
- **P1-3** 看板列头区分依赖圆点颜色,色盲不友好
- **P1-4** 空状态零引导 ("待审批 0"/"本月花费 ¥0.00"/"已启用员工 1") 不符合 "空状态有引导" 极简原则
- **P1-5** "未设预算" 弹层仅 "关闭" 按钮, 无 "去设置" 动作
- **P1-6** 数字员工 sub-tab 与 汇览"成本明细"弹层语义倒置
- **P1-7** 看板 "今日+进行中" tab 下"待处理" 多为 [P3] 设计总监, 但用户不知道这是"今日新进"

### P2 (Kitty 完美)

- **P2-1** 5 tab 图标风格不统一 (柱状图 vs 列表 vs 加号 vs 气泡 vs 网格)
- **P2-2** 灰 meta 字对比 ~3.5:1, 不达 WCAG AA 4.5:1
- **P2-3** chip 高度 ~36-40dp, 低于 MD 48dp 标准
- **P2-4** "未设预算" 提示在成本明细弹层中但不进设置, 反馈断裂
- **P2-5** "未分配" 灰色 icon + 灰色字 + 灰色 meta, 三件套灰卡难读
- **P2-6** Tab 切换无 transition, 跳转生硬
- **P2-7** a11y: 字号不可调, 老人/弱视用户无法放大
- **P2-8** 任务看板卡片左缘竖线状态 (白/黄) 颜色过近, 区分不够强烈
- **P2-9** 6 个状态缩写 (G1需求/G2方案/G3契约/G4验收/G5投产) 未解释

## 8. 推荐改进 (优先级)

1. **重命名/重贴 tab** (老板 P0-1): 工坊→会话 (或换内容), 资产→模板 (消除 demo 模板), 数字员工 sub-tab→重指本地屏 (不跳 webview)
2. **合并"新建"为 1 个入口** (老板 P0-2): 保留中央 FAB, 删弹层底"极速立项" + 项目中心大卡 + 业务本体顶 icon, 项目中心悬浮 FAB 换为页面顶部按钮
3. **修复铃铛点击** (P0-3): 接路由 /inbox (加一个 "通知" tab 或独立屏)
4. **空状态加引导** (P1-4): "0 待审批" → "恭喜, 暂无待审批事项"
