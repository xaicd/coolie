## 3. 信息架构评分 — 2/5

**问题清单**:

1. **5 tab 划分不清晰**: 汇览 (看) / 任务 (做) / + (派) / 工坊 (做) / 资产 (看) — 中间 FAB 是派单, 但工坊 tab 也是派单/沟通入口. **"派单"概念出现在 2 个 tab**, 老板 mental model 模糊。
2. **紧急熔断占卡片过大**: 仪表盘顶部 red "🚨 紧急熔断" 按钮几乎与 6 个 KPI 卡片同样大. 待审批 = 0 时, 这个按钮只是噪音 — **KPI 视觉权重排序错乱**。
3. **任务看板列定义怪**: 只有"待办池 (78)" + "待处理" 两列可见, 没有"进行中"/"已完成"/"阻塞"列, 但仪表盘统计显示 16 已完成 / 1 进行中 / 40 阻塞 / 182 待办 = 239 ≠ 看板 192 ≠ 仪表盘 199. **三处数字不一致**。
4. **资产 tab 4 sub-tab 名实不副**: "业务本体 / 项目中心 / 数字员工 / 交付产物" — "业务本体"是 Palantir ontology, 给老板看的应该是"项目 / 员工 / 产物", ontology 是给数据架构师看. 老板进资产 tab 第一眼看到 ontology 列表**反直觉**。
5. **底部 5 tab + FAB 抢占中央**: FAB (新建与语音派单) 在 5 个 tab 中央, 但 FAB 也算一个 tab 概念 — 用户感知是 "4 个 tab + 1 个 FAB" 还是 "5 个 tab"? 没有清晰标记。
6. **任务看板看不到 priority 颜色编码**: P0/P1/P2/P3/S1/S2/S3 全部挤在 [P3]/[P2]/[P1]/[S3] 灰色 chip 上, **没有任何颜色区分** — P0 阻塞任务看不出, 老板没法快速识别紧急。

## 4. 数据流评分 — 2/5

**问题清单**:

1. **任务计数三处不一致 (核心数据流 bug)**:
   - 仪表盘: "199 个任务, 完成率 8%, 已完成 16 + 进行中 1 + 阻塞 40 + 待办 182 = 239" — 仪表盘自身的 sum 与 199 差 40
   - 任务看板 header: "182 个任务" (与仪表盘"待办 182"一致, 但看板 header 应当 = total, 不是 = 待办)
   - 看板第一列: "待办池 78" (与 待办 182 不一致, 中间差 104)
   - **数据流断了三处**, 仪表盘 / 看板 header / 看板列 各自从不同源取数

2. **审批数据无回显**: 仪表盘 "0 待审批" + 紧急熔断按钮占满, 但点击 "本月花费 ›" / "0 待审批" 卡片**没有跳转到对应列表** — 数字是死的, 不通详情。

3. **通知中心 (顶部铃铛 19)** 是死数据 — 不点开就是个数, 点开是 wave270 P0-05 InboxScreen 1238 行死代码, **通知中心能力 = 0**, 跨设备一致性 (Web 派单 → App 收通知) 完全断。

4. **工坊 chat 与任务看板无同步可见性**: 工坊 chat 里给"助理"派的活 (`"派个活,或问点什么"`), **派出的任务是否回流到 任务 tab**, 看板不显示 — 数据流单向 (chat → 服务端, 但 App UI 不回流)。

5. **跨设备 (Web vs App) 一致性: 无法验证**: Web 端 (https://www.xrobinai.cn/XROA/ontology) 在 App 内通过 webview 跳, 但登入 / 状态不同步 — App 是真实用户态 (xrobinai), webview 跳过去没登录就是 ICP 备案号空白页。**Web/双端一致性 = 0**。

6. **KPI 计算口径不明**: "近 7 天运行活动 2.3 任务/天" 的"运行活动"是什么? 仪表盘**不解释指标定义** — 老板看了数据不知道是不是该信。

## 5. OpenAI FDE 落地评分 — 1/5

**问题清单**:

1. **"5 分钟上手" 不成立**: App 启动直接进仪表盘, 没有 onboarding. 老板第一次启动能看到 "汇览 / 任务 / + / 工坊 / 资产" 但**没有任何 hint 告诉老板 FAB 是派单入口**。 看 P0-03 (列表/看板切换死循环) — 老板连"列表"是按不动的都卡住。

2. **真实场景 "老板接到需求建飞书 webhook" 流程断开**:
   - 选项 A: 工坊 chat 输入需求 → 但工坊 chat 不知道有 webhook / plugin 概念
   - 选项 B: 资产 tab → 业务本体 → ontology — 这是 ontology 编辑器不是 plugin 安装
   - 选项 C: + FAB → 新建任务 → 但任务详情里没有"接 webhook"字段
   - **3 个入口都走不通** — 真实场景 = 0 覆盖

3. **派单失败/员工拒绝/超时反馈缺失**: 工坊 chat 里给助理派活, 助理跑完后只回消息 (上一条截图显示 wave139 的"信息够了。给您汇报"), **没有失败状态、拒绝、超时的可视化** — 老板不知道是助理在跑还是挂了。

4. **跨设备一致性 = 0 (核心价值崩塌)**: App 存在的意义是"老板手机端, 看员工干活进度"。但 wave270 P0-05 通知中心 1238 行死代码 + 任务计数三处不一致 + 工坊 chat → 任务看板 不同步 = **App 实质上就是老板装一个"只能看不能动"的看板**, 真正的"派单/接收通知"全部断。

5. **API 监控 / 部署状态 = 0 入口**: FDE 视角下应该有的"服务是否在线 / 上次部署 / 错误率", App 上**没有任何位置**。

## 7. 我新发现的 P0/P1/P2

### 新 P0 (架构 / 信息架构 / 数据流)

- **P0-NEW-1 任务计数三处不一致**: 仪表盘 199 vs 看板 header 182 vs 待办池 78 — 数据流断了三处. 老板日常看数据不知道信哪个. (验证依据: 截图 screen-01 + screen-09)
- **P0-NEW-2 App 不回流 chat 任务**: 工坊 chat 派单 → 服务端 → 但任务看板不显示回流. App 实质是"只读看板". (验证依据: 工坊 chat 长截图 + 任务看板缺该对话上下文)
- **P0-NEW-3 通知中心铃铛 19 是死数据**: 铃铛上有数, InboxScreen 是 wave270 P0-05 死代码, 跨设备通知 = 0. (验证依据: 顶部铃铛红点 + P0-05 死代码)
- **P0-NEW-4 仪表盘下滚触 webview 死链**: 仪表盘 scroll down 触发 `鲁ICP备2022025798号-3` webview — 备案号页面在 App 内打开, 老板误以为是产品内容. (验证依据: screen-04)
- **P0-NEW-5 跨设备 (Web/双端) 一致性 = 0**: App 是 xrobinai 登录态, 内嵌 webview 跳 https://www.xrobinai.cn/XROA/ontology 显示 ICP 空白页 — App 与 Web 数据完全不通. (验证依据: screen-04 webview)

### 新 P1

- **P1-NEW-1 FAB 派单 vs 工坊 chat 派单概念分裂**: 同一件事 2 个入口, 老板不知道选哪个. (验证依据: FAB 截图 + 工坊 chat 派活提示)

- **P1-NEW-3 KPI 数字无点击交互**: "0 待审批" / "本月花费 ¥0.00" 卡片无 onPress, 老板点不动. (验证依据: screen-03)

## 8. 推荐改进 (产品总监视角)

1. **立即修 P0-03 / P0-05 / P0-NEW-1**: 这是"App 能不能用"的硬门槛. 修复顺序: 数据流 (NEW-1) → 通知 (P0-05) → 视图切换 (P0-03).
2. **重做信息架构**: 5 tab 改为 "汇览 / 任务 / 工坊 / 资产" (移除 FAB 中间位), FAB 改为右浮动按钮 (不占 tab 位). 派单只走 FAB + 工坊 chat, 资产 tab 改 "项目 / 员工 / 产物" 三 sub-tab (移除 ontology, 移到 工坊 tab 下).
3. **任务计数三处统一**: 仪表盘 / 看板 header / 看板列 同一 source of truth = `company_tasks` count(*), 让老板看一个数字就能信.
4. **加 priority 颜色**: P0 = 红 / P1 = 橙 / P2 = 黄 / P3 = 灰 / S = 蓝 — 让老板一眼看出"哪条先做".
5. **跨设备一致性补齐**: 修复 P0-05 InboxScreen, 让 Web 派单 → App 通知能 push. 这是 App 核心价值.
6. **加 onboarding**: 第一启动用 4 卡片 hint (FAB = 派单 / 工坊 = chat / 资产 = 看 / 汇览 = 总览), 10 秒看完就 dismiss.
