## 总结

### 1. 5 屏串联的用户故事 (User Journey)
1. **全局洞察 (屏 1)**: 用户通过底部 5 Tab 点击进入 **本体**，在 `OntologyDomainListScreen` 查看 6 大顶层类型及相互包含/依赖网络，通过顶部 4 个 Chip 在业务域间横向滑动。
2. **下钻探索 (屏 2)**: 点击特定业务类型 (如 "项目") 下钻到 `OntologyInstanceGraphScreen`，按负责人真名 (铁匠/贰号/门神/墨斗/兑底渊/robin ai) 筛选过滤具体项目实例拓扑，掌握谁负责谁、谁依赖谁。
3. **元数据维保 (屏 3)**: 在屏 1 或屏 2 长按类型唤起详情卡，发现字段不足，点击 "编辑字段" 跳转 `OntologySchemaEditorScreen`，直观增删改字段定义并 `[加 存]`。
4. **全景推演 (屏 4)**: 实例过多或需要排查 cross-type 链路时，点击屏 2 右下角 `[工作台]` 浮钮，进入沉浸式 `OntologyGraphWorkbenchScreen`，在无边界画布中平移缩放、居中高亮、导出交付。

### 3. Web 端现成可抄 vs Native 需 agy 重画组件

- **Web 端有现成可直接抄逻辑/样式的组件**:
  1. **Schema 属性列表 (屏 3)**: Web 端原有的 key/type/sample 表格校验逻辑与枚举结构完全一致，RN 端直接映射为 `SectionList` + 弹窗表单。
  2. **插件管理列表与 Filter Chip (屏 5 / 屏 2)**: 顶部过滤标签与插件卡片开关逻辑完全可以直接复用 Web 端的 Store 状态管理。
  3. **节点详情卡 (屏 1 / 屏 2 弹层)**: Web 端的 Drawer/Modal 展现层只需调整为移动端底部 `BottomSheetModal`，数据接口 100% 兼容。

- **需要 agy 原生重画与调整的组件 (抛弃 force-graph 后的重构点)**:
  1. **确定性分层有向拓扑 (屏 1 / 屏 2 / 屏 4)**:
     - **原因**: 彻底剔除老板否决的 `react-native-force-graph` 动态物理力导向（在手机端性能差且易抖动）。
     - **方案**: agy 改用基于 Dagre / SVG 的**确定性分层几何布局 (Deterministic Hierarchical Layout)**，节点使用原生高性价比 View 绝对定位，连线采用固定 Bezier/Orthogonal 曲线，既保留图谱视觉，又实现 60fps 丝滑拖拽。
  2. **移动端图谱工具手柄 (屏 4)**:
     - Web 端依靠鼠标滚轮与键盘快捷键的缩放聚焦，在手机端全部重画为左下角一体化悬浮控制盘与原生 `react-native-gesture-handler` 双指捏合手势。
