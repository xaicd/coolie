## 2. 候选方案定义 (Candidate Alternatives)

### 方案 A：Web 端 15 视图直接移植原生端 (Web Legacy Migration)
- **技术形态**：将 Web 现存的 15 个 View（Graph 画布、Table、Schema、Sandbox、Datasets、Connectors、Transforms、Cognition、Capabilities、Actions、Functions、Interfaces、Dialogue、Manage、KillSwitch）全量搬运到移动 React Native 端。
- **运行特征**：使用 WebView 嵌入或 ReactFlow 移动适配，强行在 6 寸手机上渲染全局力导向图，保留一键熔断滑脱开关与复杂向导。
- **本质**：工程师自嗨式的“功能对齐”，忽视移动端人因与真实数据连通性。

### 方案 B：彻底砍除本体模块，纯保留任务工单 (Pure Task Tracker)
- **技术形态**：彻底放弃 Ontology 概念，将移动端与 Web 端的本体页面全量删除，系统退化为类似 Jira/Linear 的普通 Issue Tracker。
- **运行特征**：仅保留 `public.issues` 与 `public.heartbeat_runs`，数字员工根据普通文本 Prompt 执行，无结构化业务对象上下文。
- **本质**：因噎废食，彻底丧失 Palantir 体系的核心中枢定位与企业级业务孪生能力。

### 方案 C：Palantir 活体本体「两核一控」端到端闭环架构 (Living Ontology Two-Cores-One-Controller)
- **技术形态**：
  1. **核一：业务对象态势 (Object Explorer)**：对齐真实的 225 张业务表，映射核心实体（Company, Project, Issue, Agent, Artifact），提供**局部一跳因果链 (Local 1-Hop Chain)**，彻底砍掉移动端全局拓扑图；
  2. **核二：数据源流实时性 (Dataset Freshness)**：直连物理数据底座，呈现主表数据量、同步延迟与血缘状态；
  3. **一控：业务动词手柄 (Actions Controller)**：每个对象提供严格 ≤ 2 汉字的闭环操作动词（`推进`、`派单`、`审批`、`查看`），直接触发后台工坊执行；
  4. **四根焊钉全栈贯通**：意图入网 (Hermes MCP) ➔ 任务绑定 (ActionType) ➔ 契约施工 (WorkProducts) ➔ 终端消费 (Object Explorer Mobile)。
- **本质**：第一性原理驱动，极简使用主义，充分榨干现有 263 张物理表管网，实现业务与模型的 100% 孪生合一。

## 4. 方案深度剖析与反向穿透审查 (In-Depth Technical Auditing)

### 4.1 方案 A (Web 15 视图直接移植) 致命缺陷审判
1. **违反老板指令「本体只是业务模型，熔断毫无意义」**：在业务概念模型里做“一键熔断”是典型的工程师概念错位。熔断属于基础设施网络网关，不属于业务实体。
2. **违反老板指令「6 寸手机屏坚决不画拓扑图」**：在移动端画 150 节点的力导向拓扑图，既看不清文字，手指又点不准，纯属自嗨式炫技，完全违背极简使用主义。
3. **维护成本与性能雪崩**：Web 端使用了 5,280 行前端代码，若全量搬运到 React Native，不仅面临手势冲突、内存泄漏，还会导致原生 App 包体积急剧膨胀，且 80% 的功能点处于 0 数据空转。

### 4.2 方案 B (彻底砍掉本体) 的短视与局限
1. **丢弃了 Palantir 体系的核心护城河**：没有业务本体，AI 员工只能退化为初级聊天机器人，每次对话都需要重新解释“什么是项目、什么是工单、什么是客户”，无法沉淀企业活体知识。
2. **缺乏状态机沙箱硬护栏**：纯文本任务缺乏 ActionType 契约校验，数字员工随意篡改数据状态，无法实现信通院 1.0 报告与 CMMI Level 3 所要求的严格合规交付。

### 4.3 方案 C (两核一控) 的压倒性优势
1. **完全践行老板四大交付与使用主义总则**：
   - 极简使用主义：原生端仅保留「业务对象」与「数据源流」两个子 Tab，入口零重复；
   - 零功能膨胀：不建新表，直接吸纳 225 张真实业务表，榨干已有资产；
   - 聚焦核心与质量：每个对象配备 360 度局部一跳因果链与 ≤ 2 汉字操作动词；
   - 全维度严肃审计：端到端跑通真机模拟器，产出不可变交付证据。
2. **与人月聊IT（何明璐）本体实践深度共鸣**：
   - 放弃“构建大而全的企业级静态图谱”的虚妄幻想；
   - 确立“本体负责确定性约束，大模型负责模糊推理，代码自动化优先”的黄金铁律；
   - 将本体从“供人观赏的死图谱”改造为“驱动 AI 员工施工的操作手柄”。
