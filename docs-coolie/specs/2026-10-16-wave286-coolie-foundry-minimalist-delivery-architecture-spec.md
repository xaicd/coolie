## 一、 背景、愿景与老板最高交付总则对齐

### 1.1 老板核心原话与痛点实勘
在 2026-10-16 的高频交付复盘中，老板针对工坊运行现状作出了极其深刻的诊断并下达总则：
1. **痛点原话**:
   > *“我现在 在AGY 环境中 干活 多流畅啊, coolie-dev 中 太墨迹,繁杂,异常 , 咱们这个 窗口 就是 要建设 coolie工坊 产品, 要认真解决这个问题”*
2. **老板亲自定调的最高交付与使用主义总则 (Boss Delivery & UX Commandments)**:
   - **极简使用主义**: 系统界面与交互必须直观，绝对不能有重复功能入口；傻瓜式使用最好，用户零培训即可快速上手；
   - **零功能膨胀 (杜绝乱加功能)**: 严禁随意新增冗余功能，必须充分将系统本就具备的功能 100% 用起来、打通打透；
   - **聚焦核心与质量**: 聚焦产品核心业务主线，聚焦 AI 高效交付，聚焦代码与交付全栈质量；
   - **全维度严肃审计**: 站在新型软件交付公司负责人、Palantir FDE 体系与产品总监的严肃视角，全方位验证业务功能、排查功能缺陷，同时深度审视界面设计、空间布局与产品架构缺陷。

### 1.2 为什么 AGY 流畅？为什么过去 coolie-dev 墨迹繁杂？
墨斗站在前线架构师 (FDA) 视角深入逆向解剖两者的架构差异：
- **AGY 流畅的本质**:
  - **因果直达**: 用户输入自然语言，系统通过统一语义理解直击目标，中间无多层嵌套表单阻隔；
  - **透明反馈**: 任务以非阻塞心跳与轻量执行流推进，零形式主义空转；
  - **最小上下文**: 每次交互仅传递当前决策所必需的上下文切片，避免臃肿的数据搬运。
- **过去 coolie-dev 墨迹繁杂的根因**:
  - **重复功能入口与概念堆砌**: 同一个任务在“看板”、“列表”、“日历”、“工坊对话”、“项目树”等多个地方都有入口，用户不知道点哪里；
  - **无效轮询与扫盘风暴**: 后端每 30 秒对数十个工作区无差别执行磁盘 Git 状态扫描，抽干 CPU 资源并拉长响应时间；
  - **冗长的多阶段审批嵌套**: 缺乏场景配方与两阶段轻量确认 (2PC)，导致用户需要反复点击多个深层弹窗；
  - **全量上下文膨胀**: 任务历史信息无节制拼接，直至冲破 Linux 内核参数长度限制 (`E2BIG`) 导致异常中断。

### 1.3 商业交付工厂生态位与三层物理隔离
本架构方案严格坚守工坊平台的三层物理生命周期隔离铁律：

## 三、 四界定义与系统不变量防线 (Boundaries & Invariants)

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        企业 / 租户物理边界 (Company / Tenant Boundary) │
│  - 强制 company_id 隔离切面，跨租户查询直接 403 Forbidden               │
│  - 独立文件存储目录、独立 ExecutionWorkspace、独立预算配额账本          │
├────────────────────────────────────────────────────────────────────────┤
│                        数据访问与 RBAC 边界 (RBAC & Authority Boundary) │
│  - 法定治理级 (Human-in-the-Loop): 资金花销、员工入职/停职、高危发布     │
│  - 工程流水线级 (Inter-Agent Multi-Stage): 方案审查、代码评审、真机验收 │
├────────────────────────────────────────────────────────────────────────┤
│                        状态机流转守恒边界 (Lifecycle Invariant Boundary)│
│  - Issue 状态机严格单向闭环: todo -> in_progress -> in_review -> done │
│  - 终态完工硬门禁: 必须绑定 Git Commit SHA 与机器验收证据包              │
├────────────────────────────────────────────────────────────────────────┤
│                        资源与并发互斥边界 (Concurrency & Resource Lock) │
│  - 真机设备串行化原子锁 (device-claim): 15 分钟租约 TTL，规避抢占互污    │
│  - 单一人原子签出锁 (Single Assignee Lock): 杜绝多 Agent 冲突踩踏      │
└────────────────────────────────────────────────────────────────────────┘
```

### 3.1 Company / Tenant 租户物理隔离防线
- **数据物理标记**: 平台全盘 263 张物理表中，所有业务表一律显式包含 `company_id uuid NOT NULL`；
- **ORM 与查询拦截**: 服务端在 Drizzle / Prisma / SQL 查询层全局注入租户上下文过滤，严禁在 Controller 之外手动拼接无租户约束的裸 SQL；
- **存储与目录隔离**: 每个租户的工作区、工件附件、日志物理路径均严格以 `instances/default/companies/<company_id>/` 分隔，杜绝跨企业越权读取。

### 3.2 RBAC 与双层审批权力清单
1. **第一层：法定治理级权力 (掌柜独占审批)**:
   - 资金预算划拨与超额解冻 (`spend_money`, `adjust_budget`)；
   - 数字员工雇佣、调整岗位与解除聘用 (`hire_agent`, `fire_agent`)；
   - 生产环境正式投产与对外发版 (`production_release`)。
   - **机制**: 员工仅有提议权，掌柜在移动端或 Web 驾驶舱点击【确认】或【驳回】后方可原子生效。
2. **第二层：工程交付级权力 (数字员工交叉互审)**:
   - 铁匠 Core SWE 提交代码后，系统自动原子将工单推入 `in_review`，并通知门神 FDSE 进行真机走查；
   - 门神走查通过后盖章转由百晓生 DS 终验，若不合规打回铁匠并累加变更轮次；连续 3 轮驳回触发熔断升级通知人类掌柜。

### 3.3 状态机与物理资产守恒防线
- **工单流转不变量**: 任何工单由 `in_progress` 转为 `done` 时，控制面自动拦截断言：
  1. 必须关联有效的 Git Commit SHA（非脏树提交）；
  2. 必须挂载对应的不可变工件（`documents` / `issue_work_products`）；
  3. 若无实质资产，接口直接返回 `422 Unprocessable Entity - Missing Required Deliverable`。

## 五、 CMMI DAR 加权量化决策分析矩阵 (Decision Analysis & Resolution)

针对工坊核心交互中枢与派单执行引擎的演进方案，执行 CMMI 标准 DAR 分析（包含 2 项正选方案与 1 项阴性对照方案，总权重严格等于 100%）：

### 5.1 候选技术方案说明
- **方案 A (正选 1 · 纯聊天对话流 Chat-Only)**:
  - 类似常规 ChatGPT / Dify 界面，所有操作均通过自然语言输入对话，系统以文本流回复。
- **方案 B (正选 2 · 推荐 · 局部一跳卡片 + 场景配方直驱引擎 Card + Recipe Driven)**:
  - 融合 AGY 的轻量直达体验与移动端 6 寸屏人机工程学：顶层为极简态势感知横幅，交互主体为局部一跳因果卡片流；工坊对话支持键盘 `@` 智能选人直驱，配合 2PC 两阶段确认卡片与预制场景配方，两字按钮极速闭环。
- **方案 C (阴性对照 · 传统多级 ERP 嵌套表单中台 Heavy Form-Based)**:
  - 传统重型企业中台模式：海量表单填写、树形菜单嵌套展开、弹窗套弹窗、只读报表平铺。

## 六、 消灭“墨迹繁杂”的四大架构轻量化支柱

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 支柱一：按需节流与终态前置拦截 (消灭扫盘风暴)                           │

├────────────────────────────────────────────────────────────────────────┤

└────────────────────────────────────────────────────────────────────────┘
```

### 6.1 支柱一：按需节流与终态前置拦截
- **根因治理**: 针对 Mac 宿主机 76MB 日志与高频磁盘 I/O 问题，在 `execution-workspaces.ts` 中引入终态前置短路逻辑。对非终态工作区直接跳过，杜绝后台无谓空转；
- **心跳解耦**: 终态冷凝扫描与业务心跳物理剥离，将扫描频率收敛为 5 分钟一次，彻底还算力于前线。

### 6.2 支柱二：工坊对话 @ 直驱与 2PC 两阶段写操作
- **@ 快速派单直驱**: 用户在工坊输入框中打出 `@铁匠 修复文旅登录异常` 时，系统自动完成意图解析并原子创建工单，生成 AIP 倒计时时间盒与即刻唤醒心跳，无需用户离开对话流跳往专门的任务创建页；
- **2PC 两阶段写操作**:
  - **阶段 1 [Prepare 预检]**: 输出预检卡片（展示受影响文件、耗时预估与权限校验结果）；
  - **阶段 2 [Commit 两字确认]**: 用户轻点【确认】按钮，执行实质性变更写入；轻点【驳回】立即无痕撤销。

### 6.3 支柱三：版本化最小上下文与安全 UTF-8 截断
- **内核参数防溢出**: 引入通用截断保护机制，严格锁定命令行调用上限为 100KB（预留 28KB 安全裕量）；
- **安全切片**: 采用多字节 UTF-8 边界探测技术，杜绝截断在中文等多字节序列中间导致乱码或 `\uFFFD`。

### 6.4 支柱四：商用场景配方优先装配
- **配方优先**: 将 80% 的常见商业交付需求（如商用后端微服务模块、四位一体端到端特性）模板化固化在 `.agents/workflows/business-recipes/` 中；
- **一键编排**: 派单时直接加载对应配方的 DAG 有向无环图，自动绑定角色、前置门禁与标准产物路径，实现从意图到执行的秒级拉起。
