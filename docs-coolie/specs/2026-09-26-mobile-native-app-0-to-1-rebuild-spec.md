## 1. 核心产品红线与设计立论 (Core Product Redlines)

### 1.1 核心产品红线：彻底消灭“独立 WEB全功能 按钮”
> **产品决策 (Boss 2026-09-26 拍板)**：  
> **“我不希望还有个独立 WEB全功能 按钮，使用的很怪异。”**

在专业级移动产品（如 Slack, Linear, GitHub Mobile, Notion）中，**绝对不会在界面上放一个叫“Web 版”或“Web 全功能”的怪异按钮**。
这种设计会给用户传达一种极其不专业的潜意识：*“这个 App 是个半成品玩具，如果你想要真正的功能，请点击这个‘Web全功能’按钮跳出去吧。”*  
更糟糕的是，过去点击它还会弹出“本机未装 Coolie Web · 内置网页兜底”、“安装独立 APK”或者让用户再输入一遍账号密码。

### 1.2 真正优秀的产品逻辑：能力原生归位、润物细无声 (Natural Fusion)
- **App 本身就是完整的控制面**：
  用户使用的是 Coolie，而不是“原生端”或“Web 端”。
- **能力自然融入业务模块**：
  - 用户要看项目架构、CMMI 门禁、5+2 黄金文档、三态活拓扑、API 契约，直接在**「项目 (Projects)」**的详情页中点击查看；
  - 用户要看今日花销与团队效能，直接在**「汇览 (Cockpit)」**中看；
  - 用户要审批阻塞点，直接在卡片上滑动；
  - 用户要派工，按住中央麦克风说话；
- **实现手段对用户完全透明**：
  至于某个高密度复杂的图表（如 SkyWalking 拓扑演练、CMMI 门禁会签表）底层是由 React Native 原生渲染还是由深度定制的高性能容器呈现，**用户不需要知道，也不应该关心**。
  它们拥有统一的暗黑视觉 Token、统一的原生返回手势、统一的共享登录态，**100% 严禁出现二次输入密码，严禁出现任何“Web全功能”字样**。

3. **清理 `DashboardScreen.tsx`**：
   - 彻底删除快捷入口中的“Web全功能”图标。

### 4.2 项目详情页“全功能无缝透传”标准 (Seamless In-App Project Detail)
当用户在“项目/组织 (Projects & Org)”中点击任意项目卡片时：
1. 原生拉起项目详情导航壳，提供原生暗黑风格导航条（项目名、返回箭头、刷新图标）；
2. 内部通过认证 Session 自动桥接加载项目全功能：
   - 标签 1：任务列表 (Tasks)
   - 标签 2：CMMI 质量门禁 (G1~G5 状态机)
   - 标签 3：5+2 黄金文档 (Baseline)
   - 标签 4：RTM 需求穿透矩阵
   - 标签 5：SPC 3σ 过程控制图
   - 标签 6：SkyWalking 三态动态拓扑
   - 标签 7：DSH 多协议 API 契约沙箱
   - 标签 8：代码仓库与工作区配置
3. **关键体验标准**：
   - 用户感觉就是在 App 原生内操作项目；
   - 100% 自动携带已登录的身份凭证（通过 `/api/auth/exchange?token=...` 注入），**零二次登录**；
   - Android 物理返回键与 iOS 屏幕边缘左滑返回完美接管内部历史记录，后退到顶时退回项目列表。

### 4.3 零感知免密认证底座 (Zero-Reauth Auth Bridge)
彻底修复由于裸请求导致的重新登录漏洞：
```typescript
// 规范所有内嵌 Webview 容器的鉴权 URL 生成器
export async function buildAuthenticatedAppUrl(targetPath: string): Promise<string> {
  const token = await getWebExchangeToken();
  const cleanPath = targetPath.startsWith("/") ? targetPath : `/${targetPath}`;
  const baseUrl = `${COOLIE_WEB_URL.replace(/\/+$/, "")}${cleanPath}`;
  
  if (!token) {
    return `${baseUrl}?shell=native`;
  }
  
  // 必须走 exchange 302 附带 Set-Cookie，确保 WebView cookie jar 立刻获得有效会话
  return `${COOLIE_WEB_URL.replace(/\/+$/, "")}/api/auth/exchange?token=${encodeURIComponent(token)}&next=${encodeURIComponent(baseUrl)}&shell=native`;
}
```
