## 1. 业务背景与北极星

### 1.1 业务背景

围绕"社区/小区/园区"这一物理或社群半径，整合家政服务（日常保洁、深度清洁、月嫂/育儿嫂、保姆）、维修上门（家电维修、家居维修、水电疏通、空调清洗）、社区团购（生鲜/日用/标品/预售型）、跑腿代办（同城代取、代送、代排队、宠物寄遛）以及便民增值（洗衣、缴费、回收、二手等）四类高频业务。

当前痛点：
1. 商户分散在私域社群/小程序/电话接单，无统一订单、客户、结算、评价闭环。
2. 物业/业委会/街道办无法监管服务过程与商户履约质量。
3. 业主用户跨平台切换，缺信任背书、缺履约凭证、缺发票与售后。
4. 平台方（我们）需要承载多商户、多角色、多结算账户的合规要求。

### 1.2 北极星目标

> 在 12 个月内成为单个地级市/区可复制的「社区生活服务一站式履约中台」，连接 100+ 商户、10 万户家庭，年 GMV 突破 1 亿元，订单履约率 ≥ 95%、投诉率 ≤ 0.5%。

### 1.3 关键成功指标 (KPI)

| 指标 | 12 月目标 | 24 月目标 |
|---|---|---|
| 接入商户数 | 100 | 500 |
| 累计用户 | 10 万 | 50 万 |
| 月活 MAU | 2 万 | 15 万 |
| 月 GMV | 800 万 | 3000 万 |
| 订单履约率 | ≥ 95% | ≥ 97% |
| 投诉率 | ≤ 0.5% | ≤ 0.3% |
| 商户续约率 | ≥ 80% | ≥ 90% |

## 2. 业务范围 (In/Out of Scope)

### 2.1 In Scope (本期 v1.0 商用范围)

- 四大服务品类: 家政、维修、团购、跑腿。
- 商户 (B 端) 全生命周期: 入驻审核 → 资质管理 → 服务上架 → 订单履约 → 结算对账 → 退出门槛。
- 用户 (C 端) 全旅程: 注册/授权 → 下单/支付 → 履约追踪 → 评价/售后 → 发票。
- 运营/平台方 (O 端) 后台: 商户审核、服务审核、订单仲裁、财务对账、统计看板、合规审计。
- 多租户: 单平台承载多物业/多街道/多项目方（按 Tenant 隔离）。
- 支付结算: 微信支付 (主)、支付宝 (二期)、余额/储值卡 (二期)、对私/对公分账。
- 履约 SLA 与超时赔付规则引擎。
- 评价与信用体系 (C 评 B、B 评 C、平台强制仲裁)。
- 发票管理: 电子普票/专票申请、流转、归档。
- 数据合规: 个人信息保护法、消费者权益保护法、价格法、平台合规要求。

### 2.2 Out of Scope (本期不做)

- 外卖堂食、生鲜即时配送 (另起项目)。
- 二手商品 C2C 交易 (可作为便民增值二期接入)。
- 保险/金融分期 (合规前置条件高，二期评估)。
- 海外/跨境业务。
- 跨城调度 (单城市起步，多城市再迭代)。

### 3.3 鉴权与约束

- **多因子**: 商户主账号首次登录 + 大额提现 + 服务定价变更必须短信/人脸二次校验。
- **数据隔离**: 任何读 API 必须携带 `tenantId` + `companyId` + `roleScope` 三元组, 路由层强校验。
- **越权请求**: 默认拒绝, 记录到审计日志并触发 5xx 告警。
- **子账号授权**: 商户主账号可创建员工子账号, 限额受商户资质等级 (Lv1-Lv5) 限制。
- **外部接口**: 微信支付/小程序走 OAuth 2.0 授权码模式; 短信走第三方供应商签名。

## 4. 多租户 (Multi-Tenant) 商户接入

### 4.1 租户层级

```
Platform (中台) 1
└── Tenant (物业/街道/项目方) N
    └── Merchant (商户) M
        └── ServiceSKU (服务 SKU)
        └── Staff (员工/师傅)
        └── Order (订单)
```

### 4.2 商户入驻 7 步流程

1. **注册提交**: 商户法人/经营者身份证、统一社会信用代码、银行账户、行业资质 (如: 家政需服务业证、医护需健康证、维修需特种作业证)。
2. **资质审核**: 平台运营 1 个工作日内完成, 必要时邀请物业/业委会联审。
3. **合同签署**: 电子合同 (含服务标准/违约责任/退出机制)。
4. **账号开通**: 商户主账号 + 初始密码 + 强制修改 + 双因子绑定。
5. **服务上架**: 商户提交服务 SKU, 经平台运营审核服务定价/时长/范围, 通过后上架。
6. **试运营期**: 7 天试运营, 平台监控服务时长/投诉/退单, 通过后正式营业。
7. **保证金**: 一级商户 (家政/维修/跑腿) 缴存 2000~5000 元履约保证金, 团购商户按 GMV 比例缴存。

### 4.3 商户分级 (Lv1-Lv5)

| 等级 | 月订单量 | 投诉率 | 保证金 | 抽佣率 | 结算周期 |
|---|---|---|---|---|---|
| Lv1 | 起步 | - | 2000 | 8% | T+15 |
| Lv2 | > 100 | ≤ 2% | 2000 | 7% | T+10 |
| Lv3 | > 500 | ≤ 1.5% | 3000 | 6% | T+7 |
| Lv4 | > 2000 | ≤ 1% | 5000 | 5% | T+3 |
| Lv5 | > 5000 | ≤ 0.5% | 5000 | 4% | T+1 |

> 等级月度自动评估, 升级/降级透明可申诉, 保证金差额在下次结算时补/退。

### 4.4 商户退出

- 商户主动申请 → 冻结新单 → 30 天内结清存量订单 → 退还保证金 (扣减违约金) → 注销。
- 平台强制退出 (严重违规/失联/合规问题) → 立即冻结 → 启用商户保证金垫付用户 → 走法务流程。

## 5. 支付与结算 (Pay & Settle)

### 5.1 支付通道

| 通道 | 优先级 | 接入方式 | 资金到账 |
|---|---|---|---|
| 微信支付 (JSAPI/小程序) | P0 主 | 直连 + 服务商模式 | 实时到平台中间户 |
| 支付宝 | P1 二期 | 直连 | T+1 |
| 余额/储值卡 | P1 二期 | 平台账户 | 实时 |
| 现金/到付 (限定品类, 如维修) | P2 | 线下, 商户代收代缴 | T+1 平台对账 |

### 5.2 资金流向

```
用户支付 → 平台中间户 (受监管) → 履约完成后分账
  ├─ 商户实际收款 = 订单金额 × (1 - 抽佣率) - 平台促销补贴承担
  ├─ 平台抽佣
  ├─ 物业/项目方分成 (按合同, 默认 0, 部分项目按 5%~10%)
  └─ 退款准备金 (按 GMV 0.5% 计提)
```

### 5.3 结算规则

- **结算账期**: 默认 T+7 (Lv3 以下), Lv4 T+3, Lv5 T+1。
- **结算单生成**: 每日 02:00 自动生成 T-1 日结算单, 推送给商户主账号确认, 48 小时异议期。
- **结算执行**: 商户确认后 (或 48h 后无异议) 触发分账, 微信/支付宝实时到账。
- **退款**: 全额/部分退款实时原路退回, 平台分账部分同步回退。
- **发票**: 平台向商户开具抽佣部分增值税专票; 平台向用户开具订单金额电子普票 (按需专票)。

### 5.4 风控规则

- 单笔订单 > 5000 元触发人工复核。
- 同一用户同一商户当日累计 > 20000 元触发二次支付验证。
- 同一商户当日拒单率 > 30% 触发自动降级。
- 平台分账准备金不足时, 延迟分账并告警。

## 6. 履约与 SLA

### 6.1 SLA 等级

| 品类 | 接单响应 | 上门时间 | 服务完成 | 异常处理 |
|---|---|---|---|---|
| 家政 (日常) | ≤ 5 min | 24h 内预约 | 当场签回执 | 2h 内调解 |
| 家政 (深度/月嫂) | ≤ 5 min | 48h 内预约 | 当场签回执 | 4h 内调解 |
| 维修 (家电/家居) | ≤ 3 min | 4h 内 | 当场签回执 | 1h 内调解 |
| 跑腿 | ≤ 1 min | ≤ 60 min | 当场确认 | 30 min 内调解 |
| 团购 | - | 次日/指定日 | 提货核销 | 24h 内调解 |

### 6.2 超时赔付 (强制)

- 跑腿超时 > 15 min: 平台自动派发 5 元代金券。
- 家政/维修迟到 > 30 min: 平台自动派发订单金额 10% 代金券 (上限 30 元)。
- 团购缺货: 平台自动退款 + 10 元代金券。
- 履约失败 (师傅爽约/恶意拒单): 全额退款 + 30 元代金券, 商户扣信用分 5 分。

### 6.3 履约证据

- 上门打卡: GPS + Wi-Fi/蓝牙信标定位, 偏差 > 200m 标记异常。
- 拍照/录像: 服务前/中/后三段式强制上传, 每段 ≥ 1 张照片, 维修类必须 ≥ 10 秒短视频。
- 电子签收: 用户本人或受托人签字 (手写 or 短信验证码)。
- 异常工单: 平台客服 30 min 内主动介入。

## 7. 合规要求

### 7.1 法律合规

- **个人信息保护法 (PIPL)**: 实名信息脱敏存储 (身份证号/手机号加密, 银联级 HSM), 用户可导出/删除。
- **消费者权益保护法**: 7 天无理由 (定制类除外), 24 小时响应, 维修三包。
- **平台合规**: 平台经营者主体 + 平台内经营者 (商户) 双登记, 显著提示平台身份, 不得二选一。
- **价格法**: 服务定价须明码标价, 不得串通操纵价格, 促销须留痕。
- **发票管理办法**: 平台与商户独立开票, 平台开票至消费者, 商户开票至平台 (抽佣部分)。
- **劳动法**: 师傅端合作模式 (个体工商户/灵活用工) 须合规, 避免劳动关系认定风险。
- **特种行业**: 涉及水电、电气焊、高空作业必须持证, 平台须核验 + 留证。

### 7.2 数据合规

- 个人信息分类分级 (P1-P4), 不同等级不同存储与访问策略。
- 跨境传输禁止 (默认全部境内存储), 仅运维例外需走审批。
- 第三方共享最小化, 支付/短信/地图供应商须签数据处理协议 (DPA)。
- 重要操作 (登录/支付/退款/分账/删除) 写操作日志, 留存 ≥ 3 年。
- 季度合规自评 + 年度第三方审计。

### 7.3 资金合规

- 平台中间户必须为持牌支付机构备付金账户或银行专户。
- 资金流与信息流分离, 平台不直接接触沉淀资金。
- 反洗钱: 单日 > 5 万 / 单月 > 20 万自动报送大额可疑。

## 8. 非功能性需求 (NFR)

### 8.1 性能

| 指标 | 目标 | 备注 |
|---|---|---|
| 核心 API P99 响应 | ≤ 300 ms | 下单/支付/订单查询 |
| 首页加载 P95 | ≤ 1.5 s | 首屏 + 关键资源 |
| 跑腿推送延迟 | ≤ 3 s | 订单 → 骑手 App |
| 后台运营查询 P95 | ≤ 2 s | 报表/统计 |
| 静态资源 | CDN 命中率 ≥ 95% | |

### 8.2 容量与并发

- 日订单峰值: **5 万单/日** (12 月目标 8000 单/日, 预留 6× 余量)。
- 秒杀场景 (团购开团): 单 SKU 1 万 QPS, 限流/排队/防超卖。
- 在线用户: 同时在线 5 万, WS 长连接 8 万。
- 跑腿推送峰值: 1000 QPS, 推 → 接 ≤ 5s。
- 文件上传 (履约照片/视频): 单文件 ≤ 50 MB, 总量每日 ≤ 5 TB, 走对象存储 + CDN。

### 8.3 可用性 (SLA)

| 系统 | 可用性目标 | 月度停机 |
|---|---|---|
| 用户端 C | 99.95% | ≤ 21.6 min |
| 商户端 B | 99.9% | ≤ 43.2 min |
| 运营后台 O | 99.5% | ≤ 3.6 h (可降级) |
| 支付通道 | 99.99% (依赖微信/支付宝) | - |

- 多 AZ 部署, 同城双活, RPO ≤ 5 min, RTO ≤ 30 min。
- 每日全量备份, 异地容灾, 季度演练。

### 8.4 安全

- **应用层**: OWASP Top 10 全部覆盖, 自动化渗透测试每周一次。
- **数据层**: 传输 TLS 1.3, 存储 AES-256, 敏感字段字段级加密。
- **身份**: 强密码 + 双因子, 商户主账号强制, 用户可选。
- **风控**: 设备指纹 + 行为分析 + 规则引擎, 实时拦截黄牛/刷单/套现。
- **密钥**: HSM 管理, 永不落盘明文, 季度轮转。
- **漏洞**: 24h 内响应高危, 7 天内修复, SLA 写入 SRE 巡检。
- **合规**: 等保 2.0 三级 (目标), 隐私影响评估 (PIA) 上线前必备。

### 8.5 可扩展性

- 服务化拆分 (用户/订单/支付/履约/结算/商户), 独立伸缩。
- 读写分离, 订单读写比 1:5, 历史订单冷热分层 (近 3 月热, 3 月+冷)。
- 事件驱动 (Kafka/Pulsar), 关键事件 (订单创建/支付/分账) 全链路追踪。
- 第三方能力插件化 (支付/短信/地图/客服 SDK), 配置接入。

### 8.6 可观测性

- **Metrics**: Prometheus + Grafana, 核心 RED (Rate/Error/Duration) + USE (Utilization/Saturation/Errors) 看板。
- **Logging**: 结构化 JSON 日志, 链路 TraceID 贯穿, 集中 ELK/Loki 7 天热 + 30 天冷。
- **Tracing**: OpenTelemetry, 关键路径采样 100%, 其它 10%。
- **告警**: 错误率 > 1% / P99 > SLO / 资金异常 5 min 内告警。
- **业务监控**: GMV/订单/商户活跃/投诉率 实时大盘, 5 min 延迟。

### 8.7 可维护性

- 单服务代码 < 1 万行, 团队 < 5 人可维护。
- 文档: 架构/HLD/LLD/API 全部上 OpenAPI, 自动生成。
- 变更: 灰度发布, 蓝绿/金丝雀, 回滚 SOP 5 min 内。
- On-call: 7×24, 主备轮值, 工单响应 ≤ 15 min。

### 8.8 国际化与本地化 (预留)

- 字符集: UTF-8 全平台。
- 货币: CNY 主, 预留 HKD/SGD。
- 时区: 默认 Asia/Shanghai, 用户可改。
- 农历/节假日: 家政与跑腿节假日需特殊调度, 二期支持。

### 8.9 兼容性

- 微信小程序: 基础库最低 2.30.0, 兼容 iOS 13+ / Android 7+。
- 商家端: Web 自适应 + 原生 App (iOS/Android) 双端。

## 10. EARS 验收准则 (Easy Approach to Requirements Syntax)

> 满足条件即视为该需求"已交付"。

### 10.1 业务能力 (Ubiquitous / Event-driven / State-driven / Optional / Unwanted)

| ID | 类别 | 验收描述 |
|---|---|---|
| EARS-001 | Ubiquitous | **The** 中台 **shall** 提供用户注册、登录、实名认证功能, 并符合 PIPL 要求. |
| EARS-002 | Event-driven | **When** 用户提交订单 **then** 中台 **shall** 在 3 秒内冻结对应库存/服务额度并创建支付单. |
| EARS-003 | Event-driven | **When** 用户完成支付 **then** 中台 **shall** 在 5 秒内向商户推送订单. |
| EARS-004 | Event-driven | **When** 师傅点击"已到达" **then** 中台 **shall** 在 2 秒内记录 GPS + 设备信标并通知用户. |
| EARS-005 | Event-driven | **When** 用户确认签收 **then** 中台 **shall** 在 10 秒内触发资金分账计算, 24 小时内进入结算单. |
| EARS-006 | State-driven | **While** 商户处于"试运营"状态 **the** 中台 **shall** 限制其单日订单数 ≤ 5 单. |
| EARS-007 | State-driven | **While** 商户保证金 < 应缴阈值 **the** 中台 **shall** 冻结其新订单接收. |
| EARS-008 | Unwanted | **If** 同一用户 10 秒内连续下单 > 5 次 **then** 中台 **shall** 触发人机验证 (图形验证码). |
| EARS-009 | Unwanted | **If** 商户当日拒单率 > 30% **then** 中台 **shall** 自动降级并暂停派单 24 小时. |
| EARS-010 | Optional | **Where** 用户开启短信通知 **the** 中台 **shall** 在关键节点发送短信 (下单/支付/师傅到达/完成/退款). |
| EARS-011 | Ubiquitous | **The** 中台 **shall** 对所有写操作写入审计日志, 字段至少含 `actorId/action/targetId/before/after/traceId/timestamp`. |
| EARS-012 | Ubiquitous | **The** 中台 **shall** 实现 RBAC, 任何接口拒绝无 `tenantId+roleScope` 越权请求并记入审计. |
| EARS-013 | Event-driven | **When** 跑腿订单超时 15 分钟未签收 **then** 中台 **shall** 自动派发 5 元代金券并通知用户. |
| EARS-014 | Event-driven | **When** 平台财务确认结算单 **then** 中台 **shall** 在 24 小时内通过微信/支付宝完成分账. |
| EARS-015 | State-driven | **While** 用户处于"风控熔断"状态 **the** 中台 **shall** 拒绝其下单/支付/退款直至人工解除. |

### 10.2 非功能性验收

| ID | 验收描述 |
|---|---|
| NFR-001 | 中台核心 API P99 响应 ≤ 300 ms, 在日订单 5 万/日压测下保持 24h 无故障. |
| NFR-002 | 中台用户端可用性 ≥ 99.95%, 月度停机 ≤ 21.6 min. |
| NFR-003 | 支付通道可用性 ≥ 99.99% (含微信/支付宝 SLO), 资金 0 差错. |
| NFR-004 | OWASP Top 10 自动化扫描 0 高危, 季度第三方渗透测试 0 中危. |
| NFR-005 | 个人信息加密存储 (AES-256 字段级), 传输 TLS 1.3, 第三方审计 0 重大问题. |
| NFR-006 | 关键事件 (订单/支付/分账) OpenTelemetry 100% 采样, 链路 TraceID 全程贯通. |
| NFR-007 | 多 AZ 同城双活, RPO ≤ 5 min, RTO ≤ 30 min, 季度演练通过. |
| NFR-008 | 退款时效 P99 ≤ 60s, 履约证据完整率 ≥ 99%. |
| NFR-009 | 等保 2.0 三级测评通过, PIA 报告归档. |
| NFR-010 | 商户入驻从提交到试运营 P95 ≤ 24h, 平台运营审核 1 个工作日完成. |

## 11. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 师傅端灵活用工合规 | 高 | 二期接入第三方灵工平台, 一期用个体工商户 + 协议明确 |
| 商户保证金池流动性 | 中 | 引入银行/保险共保机制, 平台分账准备金按 GMV 0.5% 计提 |
| 跑腿调度冷启动 | 高 | 优先接入美团/达达聚合分发, 二期自建 |
| 平台合规主体责任 | 中 | 显著提示平台身份, 商户合同明确, 平台"通知-删除" SOP 完善 |
| 个人信息保护 | 高 | 第三方 DPA + 等保三级 + 隐私设计 (PbD) 嵌入架构 |
| 黄牛/刷单 | 中 | 设备指纹 + 行为分析 + 黑名单, 季度复盘 |
| 突发公共事件 (如疫情) | 中 | 业务降级预案, 仅保留紧急刚需品类 |

## 12. 待老板拍板的关键问题

> 评审时, 老板只需要回答以下 5 个二选一, 其余细节由 PM 推动细化。

1. **业务范围**: 是否本期 v1.0 同时覆盖「家政 + 维修 + 团购 + 跑腿」四类, 还是先做「家政 + 维修」(跑腿/团购二期)?
2. **租户层级**: 平台默认 1 个 Tenant = 1 个物业/项目方, 是否支持嵌套 (如物业 → 楼栋 → 单元), 还是 v1.0 只做单层?
3. **结算账期**: Lv3 及以下商户默认 T+7, 是否接受? 平台现金流压力评估待 COOA-92 财务模型细化。
4. **师傅端合作模式**: 一期默认个体工商户 + 合作协议, 是否接受? 二期再考虑是否接入灵工平台 (已有 SaaS 如: 豆豆打工等)。
5. **数据中台**: 是否在 v1.0 同步建设商家数据看板 (C 端行为漏斗 + B 端 GMV/履约), 还是先做交易闭环, 数据看板 v1.1 单独排期?
