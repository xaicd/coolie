## 6. 性能热点

1. **FlatList 虚拟化被主动关闭（最严重）**：`App.tsx:970-971` `scrollEnabled={false}` 的 FlatList 嵌在外层 `ScrollView`（818）里，50 条任务（`listIssues({limit:50})`）**全量渲染**；且每行一个 `StatusDot`，`in_progress` 行 `pulse=true` → 每行一个常驻 `Animated.loop`。
2. **本体页 N+1 预取**：`loadDomains`(104–135) 每次刷新都对前 5 个域各发一次 `getOntologySnapshot(companyId, id, 50)`，无去重无缓存无并发控制；打开详情再发一次 300 条。10 个域 = 11 次请求。
3. **逐键盘请求 + 全屏 spinner 抖动**：`ArtifactsScreen.loadArtifacts` 依赖 `searchQuery`(236–253)，`useEffect[loadArtifacts]` 使**每次输入都 `setLoading(true)`**，整屏 spinner 闪一下；且 `kind` 过滤先在服务端过滤、又用 `filteredList`(222–232) 客户端二次过滤（重复劳动）；`onSubmitEditing={loadArtifacts}` 的语义被 useEffect 架空。
4. **零 memo 化**：全仓 0 处 `React.memo`；`renderItem` 均为内联匿名函数，任意 `setState` 触发全列表重建。`useMemo` 也极少（Ontology 1、Dashboard 0、App 0），`App.tsx` 有 33 处 `onPress` 内联箭头。
5. **未装 FlashList**：`package.json` 只有 RN 0.76.5，未安装 `@shopify/flash-list`；长列表全是 FlatList/ScrollView。对照 PRD AC-2.2.1（20 文件 / 2000 行变更、首屏 ≤400ms、滑动 ≥55fps）存在硬差距。
6. **无退避的轮询**：`QuickApprovalCard` 固定 6s `setInterval` 拉 `listApprovals`，无 AppState 前后台判断、无失败退避，且 `catch {}` 静默吞错。
7. **弹窗内的重活**：`ArtifactsScreen` Modal 对非图片产物一律塞 `CodeViewerWebView(previewText)` → 同一段文本在 RN 与 WebView 各存一份；`CodeDiffScreen` 全量 diff 走 WebView CodeMirror。
8. **启动即打网络**：`HomeScreen:649-653` `checkAppVersion()` + `useOTA`，Dashboard 又有一个 OTA 按钮，均无节流/缓存。

## 7. 驾驶舱化差距

> 本地**没有** `slopus/happy` 克隆（`find ~/workspace` 无命中），因此以仓库自带 `doc/plans/2026-09-19-mobile-cockpit-prd-v2.md` 第 3 节确立的 4 条标准为基准（该 PRD 明确声明以 `slopus/happy` 为标杆）。

### 7.1 对照 PRD 第 3 节四条交互标准

| PRD 标准 | 现状 | 差距 |
| --- | --- | --- |
| ① 会话流式驱动、轻量渲染（逐字渐显、杜绝全量刷新抖动） | BoardChatScreen 已接 SSE | 其余页面是"整屏 loading → 整屏结果"；`ArtifactsScreen` 逐键盘 spinner 是反例。**缺骨架屏（skeleton）与乐观更新** |
| ② 移动端 Diff 极简渲染（单列、按文件折叠、55fps） | `UnifiedDiffViewer` 已单列；折叠在 CodeDiffScreen | **缺虚拟化（无 FlashList）**、折叠状态不持久、无大文件性能验证 |
| ③ 审批主动拦截 + 一键裁决 | `QuickApprovalCard` 已实现（绿批准 / 红驳回 / 驳回必填理由）——**已达标，属领先项** | 是 6s 轮询不是推送；只在"任务"tab 上悬浮，不全局常驻 |
| ④ 离线发件箱与幂等 | `createIssue` / `voiceDispatch` **均未传 idempotencyKey** | **未实现**，弱网重试会重复发单 |

### 7.2 "一眼掌控"四要素的断链

- **钱**：Dashboard 有预算水位 ✅，但成本只在汇览页；任务详情要靠 `IssueCostRow` 单独再拉一次。
- **人**：Agents + Dashboard 智能体团队 ✅，空闲度只有 Dashboard 一处。
- **活卡哪**：Dashboard 审批卡 ✅，但 `onOpenApprovals` 只是 `setTab("tasks")`（`App.tsx:791`）→ **落在任务列表而不是审批队列，链路断在这里**。
- **本体安全闸门**：`EmergencyKillSwitch` ✅ 领先（滑动防误触 + 审计理由 + 50ms 语义）。

### 7.3 形态差距（happy 的"随身、流式、轻盈、即决"）

- **结构相反**：本 App 是"一屏一个大 ScrollView 堆 N 个详情卡"——`DashboardScreen` 单个 ScrollView 塞 10 个区块、本体详情塞 8 个区块；happy 是单任务流式会话流。
- **无导航栈**：系统返回键无感知，无手势返回，无转场动效。
- **无骨架屏**，空态用 emoji 而非设计图形（happy 用图形化空态）。
- **无键盘避让策略**（评论输入、标题编辑都在 ScrollView 底部）。
- **硬编码深色**：`C` 为唯一主题，无浅色/跟随系统。

### 7.4 视觉规范自破（Linear 规范层面）

- **字重越界**：DESIGN 规定三档 400/500/600、禁 700/800，实际 `AgentsScreen.tsx:601` h1 `fontWeight:"700"`、`DashboardScreen` `redBadgeText` 700、`App.tsx` `profileAvatarText`/`profileName`/`settingsTitle` 均 700。
- **投影**：Linear 不用阴影，`PrototypeSandboxScreen` 有 5 处 `shadow*`/`elevation`，`EmergencyKillSwitch`/`QuickApprovalCard` 也用了。
- **裸色值 204 处**（`screens/` + `components/`）：`rgba(255,255,255,0.02)` ×22、`rgba(239,68,68,0.28)` ×6、`rgba(239,68,68,0.2)` ×6，另有 `#FFFFFF`/`#050607`/`#0F1011`/`#38BDF8` 等。
- **紫色双源漂移**：`C.brand=#5E6AD2` 与 `C.accent=#7170FF` 并存，Agents 用 `rgba(113,112,255,…)`（accent 系），`QuickApprovalCard` 的 `TYPE_CONFIG` 同时用 `rgba(113,112,255)` 和 `rgba(94,106,210)` 两种紫。
- **已确认的功能缺陷 3 处**（本体页）：
  1. `filter === "locked"` **没有过滤分支**（306–316）→ 点"已锁定"实际显示全部域。
