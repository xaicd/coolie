## 1. 业务背景与老板决策 (Boss Directive & Background)

### 1.1 老板原话
> 「业务本体页面功能得重新设计一下吧」  
> 「选 v0.6.19 那种：L1 域 chip + L2 类型列表 + L3 实例下钻（纯列表）」

### 1.2 核心问题复盘 (Why Redesign)
1. **拓扑白噪声**: 原 `OntologyDomainListScreen` 默认强行渲染复杂图谱画布，在中小规模团队或初始化阶段（实体数 < 30），拓扑节点稀疏甚至孤立，用户难以快速概览业务实体全貌。
2. **移动端手势冲突**: 画布拖拽/缩放手势经常与外层垂直列表滑动、返回上一级手势争抢触控焦点，导致操作卡顿和迷失。
3. **层级不直观**: 业务概念模型 (L1 域)、逻辑类型模型 (L2 类型)、物理运行时实例 (L3 实例) 缺乏自上而下的线性导航递进。

### 1.3 设计决策与四条架构防线 (FDA Boundaries)
1. **公司物理隔离防线 (Tenant Isolation)**: 所有 L1 域、L2 类型、L3 实例均严格以 `company_id` 为第一检索和写入锚点，禁止跨企业泄露。
2. **列表为主、图谱为辅**: 默认进入纯列表视图，右上角提供轻量化 `[📋 列表 / 🔗 图谱]` Toggle。
3. **稀疏数据降噪保护 (Sparse Data Guard)**: 统计当前域内全部实体实例总数。若 `totalInstances < 30`，点击图谱时自动弹出「实体较少建议列表」温和提示横幅，提供一键切回。
4. **单向三级下钻路径**:
   - `L1 Domain`: 顶部横向水平滑动 Chips，快速切换业务域；
   - `L2 EntityType`: 垂直卡片清单，高密度呈现实体类型、实例量与关系数；
   - `L3 Instance`: 面包屑导航下钻具体实例，提供检索、排序与快速查看。

## 3. 技术契约与状态机规范 (Technical Contracts for SWE)

### 3.1 视图状态机定义 (View Mode State Machine)
```typescript
export type OntologyViewMode = "list" | "graph";

export interface OntologyDomainState {
  viewMode: OntologyViewMode; // 默认 "list" (v0.6.19 经典)
  activeDomainId: string | null; // null 表示 "全部"
  selectedTypeId: string | null; // null 表示处于 L2 列表，非 null 进入 L3 实例下钻
  searchQuery: string;
  sortBy: "count" | "updatedAt" | "name";
}
```

### 3.2 稀疏数据门禁规则 (Sparse Graph Gate)
```typescript
export const SPARSE_GRAPH_THRESHOLD = 30;

export function isGraphSparse(totalInstances: number): boolean {
  return totalInstances < SPARSE_GRAPH_THRESHOLD;
}
```
- **触发机制**: 当用户点击 `[ 🔗 拓扑图谱 ]` 且 `isGraphSparse(totalCount)` 为 `true` 时，激活提示横幅；
- **回退机制**: 用户点击横幅上的 `一键切回纯列表`，状态立即无缝归位至 `viewMode = "list"`。
