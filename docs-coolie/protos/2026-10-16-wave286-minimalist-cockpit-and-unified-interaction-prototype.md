## 一、 人机工程学设计原则与交互规范

1. **6 寸屏单手 1/3 下部热区盲操法则**:
   - 核心业务触控热区（操作按钮、快捷动词、抽屉拉柄）严格收敛于屏幕中下部 1/3 区域，契约单手大拇指舒适握持轨迹；
   - 绝不把主要提交或审批动作置于屏幕左上角等死角区域。
2. **零重复功能入口 (Single-Source-of-Truth Ergonomics)**:
   - 全系统彻底消灭重复入口：任务推进唯一入口在卡片一跳，会话派单唯一入口在工坊对话输入框；
   - 用户无需学习“该去看板找还是去列表找”，界面聚焦直观的一跳因果流。
3. **两字动词手柄 (Two-Character Action Pad)**:
   - 界面上所有按钮文案严格收敛为 2 个汉字：【派单】【确认】【驳回】【发布】【中止】【推进】【查看】；
   - 消除“点击提交修改”、“立即开始执行”等长文案造成的视觉污染与小屏折行撑爆。
4. **黄金 5 槽位绝对对称底栏 (Golden Symmetrical 5-Slot Dock)**:
   - 底部 Dock 固化为经典对称布局：`[ 汇览 ]   [ 任务 ]   [  ＋  ]   [ 工坊 ]   [ 资产● ]`；
   - 无论页面如何滚动或层级如何流转，底栏槽位与间距绝对守恒，禁止任何偏心漂移。
5. **局部一跳因果抽屉 (Local 1-Hop Bottom Sheet)**:
   - 拒绝深层多级跳转与复杂路由压栈；
   - 点击任一实体（项目/工单/员工/产物），自底向上滑出 360 度局部一跳抽屉，明确展示【前驱来源】➔【当前态】➔【后继产物】，就地两字闭环。

## 三、 四态穷举与极限小视口自适应规约 (4-State & Viewport Defense)

### 3.1 四态状态机全覆盖 (4-State Exhaustion)
为杜绝“白屏”、“假死”、“无数据时无提示”等缺陷，所有原型组件强制实施四态契约：
1. **加载态 (Loading)**: 骨架屏秒级占位（不使用全局打转 Spinner 遮挡全屏），明确呈现加载区域；
2. **正常态 (Loaded)**: 因果卡片流平滑淡入，数据字段逐字映射，按钮处于可交互就绪态；
3. **无数据态 (Empty)**: 展示标准轻量插画与引导动词按钮（例如：暂无进行中任务，点击【派单】一秒立项）；
4. **异常态 (Error)**: 界面友好呈现错误原因（如网络超时或租户越权），提供两字【重试】按钮，绝不出现未捕获红屏报错。

### 3.2 极限视口防御 (320px Viewport Defense)
- **容器安全边界**: 卡片容器一律采用 `width: '100%'`, `maxWidth: 380`, `alignSelf: 'center'`；
- **文字防溢出**: 标题文本强制添加 `numberOfLines={1}` 与 `ellipsizeMode="tail"`，绝不因超长文字撑爆容器宽度；
- **按钮尺寸合规**: 移动端两字操作按钮严格采用 `minWidth: 72`, `height: 36`, `paddingHorizontal: 12`，在 320px 视口下横向并排两按钮仅占用 160px，保留 160px 安全留白，绝对 0 折行。
