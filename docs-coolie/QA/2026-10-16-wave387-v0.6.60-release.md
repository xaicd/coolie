## 4. 偏差与处置 (诚实登记)

1. **版本号 0.6.59 → 0.6.60 (与调度令字面不一致, 已请示确认)**
   0.6.59 已发 (wave386), 无法重发 (脚本硬门禁 + tag/version.json 已占用)。改发 0.6.60 一次交付
   wave386+wave388, 满足老板「一次性发版包含两者」的真实诉求。

2. **`release-app.sh` 在 `[10/11]` web 段健康验证中断 (exit 1)**
   报错 `❌ web 段健康验证失败: GET / 返回 HTTP 000000`。000000 = curl 连接层失败 (非 HTTP 错误),
   与仓库已知「本机代理干扰远端连通」现象一致, 属瞬时抖动。复核: 中断后 `GET https://xrobinai.cn/`
   连测 3 次均 `200`, `api/health` commit 已是 `bb187541a` —— **web 段实际部署成功**, 仅脚本内那一次
   curl 探测失败。处置: 未重跑整个发版 (会因版本已 0.6.60 被拒且重复部署), 改为手工补跑脚本本应在
   `[11/11]/[12/12]` 执行的两件事 —— 4 护栏 (全绿) + tag。APK/COS/version.json/OTA/server 均在中断前
   已完成, 无二次上传风险。**建议**: 给 release-app.sh 的 web 健康验证加 2 次重试 (低风险增强, 非本波范围,
   与 wave384/wave387-0.6.59 同源)。

3. **wave388 的服务端核心修复早已部署 (非本波重复劳动)**
   wave388 真因在服务端 (`plugin-multimodal/src/asr/tencent.ts` `VoiceFormat` 数字→字符串), 已于
   wave388 部署生产并真机链路验证 (201 + 正确文字)。本波 0.6.60 装入的是 wave388 的**客户端韧性**
   (`useRecorder.stop()` 返回 uri + `voiceDraft.ts` 失败保录音 + `BoardChatScreen` 权限「去设置」)。

4. **本地 tracked `version.json` 保持非脚本托管** (停在 0.6.27) — 沿用历史先例, 远端为真值。
