# 文章主线

老板转发这篇的目的是——**判断 FDE 是不是换皮的驻场外包**。文章分四部分：

## 一、FDE 火起来，不是因为企业突然爱买驻场服务

**需求侧**：超过 70% 企业在至少一个业务职能里试过生成式 AI，但超过 60% 还停在试点阶段。Demo 早就做得出来，卡住它们的是 Demo 之后的一长串工作——接系统、嵌流程、过合规、拿出业务结果。

**80/95/99 模型**（报告核心）：
- 0-80%：通用大模型 + 简单 Prompt，一天就能搭出"挺好用"的原型
- 80-95%：模型在特定场景出错，得补规则、标数据、建测试集
- 95-99%：1% 错误也可能出大事（客服答错 → 品牌事故）
- **报告原话**："FDE 不是做从 0 到 80% 的活，而是做从 80% 到 99% 的活。"

**供给侧 3 成本门槛降**：
- 行业知识蒸馏：现场问题 → 脚本/工具/原型（不用排队后方）
- 定制开发：过去不划算的小场景定制，现在用更小团队就能做价值验证
- 复合型人才：AI 补齐一部分工程/文档/产品能力，业务技术两头上手的人好找了

**市场信号**：Indeed 上 FDE 招聘从 2025-04 的 643 条涨到 2026-04 的 5330 条。YC 孵化的公司里上百家在招 FDE，3 年前几乎为零。Palantir 前高管 Bob McGrew：FDE 模式 AI 公司前 18 个月 ARR 增速平均比同行快 3 倍，客户成功团队规模只有同行 1/3。（"快 3 倍"要打折——说话的是 Palantir 前高管，且能被拿出来讲的通常都是做成了的公司。）

## 二、判断是不是 FDE，看项目结束后剩下什么

报告反对按"干什么活"划分，主张按"项目结束后手里剩下什么"划线——区别体现在三步：

1. **重新定义客户问题**：嘴上说的需求 → 真正值得做的业务问题
2. **交付可验证的结果**：不只是功能能用，得证明接听率/转化率/处理时长/人效确实变好
3. **把现场经验带回来**：行业里反复出现的流程/接口/测试/合规 → 沉淀成可复用的平台能力

**报告原话**："缺少第三步，FDE 就会退化为高端外包。"

**4 档分级表**（整份报告最好用的一张）：

| 项目结束后剩下什么 | 算什么 | 案例 |
|---|---|---|
| 只留给客户一个系统 | 外包 | 只负责上线，不负责结果 |
| 带回一些经验，但无法复用 | 项目制交付 | 经验沉淀在脑子里，换项目归零 |
| 沉淀为 Skill / 模板 / 产品能力 | FDE | 沉淀后显著降低下个客户成本 |
| 可规模化 | FDE（成熟态）| 单位价值对应的现场投入应该下降 |

**Bob McGrew 度量原则**："如果第一个客户需要 10 人月，第十个同类客户仍然需要 10 人月，模式就没有跑通。"

这把尺子很残酷——不少挂着 FDE 牌子的团队恐怕都够不着第 4 档：做到第十个客户还跟第一个一样费人。

**为什么不是谁都能走到第 4 档**：
- 延迟收益：沉淀的投入要先做、要先投入，后回收
- 团队能力：需要带回来 + 沉淀为可复用模板，需要复合型人才
- 数据飞轮：模板越多，下个客户所需人力越少，形成自我增强

## 三、FDE 与 Coolie 工坊的共鸣

报告强调的"翻译 + 验证 + 带回"三步法，与 Coolie AGENTS.md §12 公理二"五大合一顶层审视视角矩阵"完全同构：

| 报告 | Coolie 对应 |
|---|---|
| 重新定义客户问题 | 新型软件交付公司负责人视角（CEO / 商业交付总控）|
| 交付可验证的结果 | CMMI 5 质量与交付总监视角（No Artifact, No Done）|
| 把现场经验带回来 | Paperclip 总产品架构师视角（控制面第一公民）|
| 沉淀为 Skill / 模板 | Palantir 活体本体架构师视角（项目进厂即本体域）|
| 4 档分级的临界线 | 极简人机产品总监视角（大胆做减法）|

**特别是"项目结束后剩下什么"4 档分级，与 Coolie §18 工坊即本体北极星直接共振**：
- 1 档（外包）= 一次性交付，无积累
- 2 档（项目制）= 经验在脑子里
- 3 档（FDE）= 沉淀为 Skill / Skill 库 / 工作模板（**这正是 Coolie 核心**）
- 4 档（可规模化）= 第 3 档 + 数据飞轮（**这是 Coolie v0.6.51 已经在做的**——acpx dispatch + 派单 receipt + G1-G5 证据账本 + 263 表复用）

## 五、给老板的 3 条建议

1. **Coolie 自研产品经理 = 天生 FDE**（报告原话）—— Hermes 应该把"翻译 → 验证 → 带回"作为日常派工的硬流程。
2. **不要让"只交给客户系统"的 1 档外包团队挂 Coolie 牌子**——对外接单前必须证明第 3 档（沉淀 Skill）。
3. **第 4 档可规模化是 Coolie 终极目标**——263 表复用 + Skill 库 + 派单 Receipt + 证据账本，就是 Palantir Foundry 的国内版本。
