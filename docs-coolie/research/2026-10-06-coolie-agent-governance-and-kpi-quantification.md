## 一、 深入学习：Coolie 工坊产品底层究竟是如何管理 Agent 的？

很多团队把 Agent 当成简单的“系统提示词 (Prompt) + 聊天窗口”。而 Coolie 工坊能够稳定调度 6 大数字员工打赢上百个波次的攻坚战，是因为其底层运行着一套**严肃的企业级控制面产品架构**：

## 二、 6 大岗位角色精细化职责矩阵 (RACI & Exclusive Deliverables)

为消灭“大家都做开发、出了事踢皮球”的混乱，对 6 位员工的**主责、独占产出、严禁行为与交接条件**进行绝对清晰化界定：

```
                    ┌──────────────────────────────────────────────┐
                    │            Hermes (PM / 项目总调度掌柜)        │
                    │   需求翻译 / 7要素派单 / 门禁推进 / 算力ROI把控│
                    └──────────────────────┬───────────────────────┘
                                           │ 派单与验收
                                           ▼
      ┌────────────────────────────────────┼────────────────────────────────────┐
      │                                    │                                    │
      ▼                                    ▼                                    ▼
┌───────────────┐                  ┌───────────────┐                  ┌───────────────┐
│  墨斗 (FDA)   │ 架构约束         │  铁匠 (SWE)   │ 契约实现         │  门神 (FDSE)  │
│  前线架构师   ├─────────────────►│  平台核心研发 ├─────────────────►│  前线全栈交付 │
│  选型/模型/边界│                  │  0编译/单向依赖│                  │  真机/四态/全栈│
└───────────────┘                  └───────────────┘                  └───────┬───────┘
                                                                              │ 提交验收
                                                                              ▼
┌───────────────┐                  ┌──────────────────────────────────────────────────┐
│ 兑底渊 (PRE)  │ 生产指纹拦截     │                   百晓生 (DS)                    │
│ 产品可靠性专家├─────────────────►│              部署战略与业务方案专家              │
│ 7处一致/拨测  │                  │       【用户视角主审官】业务Outcome一票否决权      │
└───────────────┘                  └──────────────────────────────────────────────────┘
```

### 1. Hermes（掌柜 / PM / 总调度）
- **Palantir 作战力量**: **Echo (战略统领与调度主帅)** — “Echos win”。
- **唯一主责**: 老板口语的“全层级翻译 (Translation)”、任务 WBS 拆解与 7 要素派单、CMMI 阶段推进、团队整体算力 ROI 负责。
- **独占产出**:
  - `7 要素派单简报 (Brief)`；
  - `Dispatch Receipt` 与工单状态机推进；
  - `周度复盘与高管态势报告`。
- **严禁行为 (Anti-Patterns)**:
  - 严禁自己动手写具体业务代码（代码工作必须派发给墨斗、门神或铁匠）；
  - 严禁口头一句话甩单（缺 7 要素中任一项不得派单）。
- **协同交接契约**: 向墨斗/铁匠派发前，必须保证分支干净、文件白名单不交叉。

### 2. 墨斗（FDA / 前线架构师）
- **Palantir 作战力量**: **Delta (前线架构与领域规划)** — “Deltas build / Lead”。
- **唯一主责**: 在写第一行代码前画死组织/租户隔离边界、领域模型边界、RBAC 权限边界与不可篡改事务守恒。
- **独占产出**:
  - `CMMI G1 架构设计说明书 (HLD)` 与领域模型 Drizzle/Prisma Schema；
  - `CMMI DAR 加权决策矩阵`；
  - `跨域 Seam Graph 边界规范`。
- **严禁行为 (Anti-Patterns)**:
  - 严禁允许跨域内部 Service/DAO 相互依赖；
  - 严禁为了单一小功能随意扩表或增加宽表冗余。
- **协同交接契约**: 移交给门神/铁匠时，必须明确指出租户隔离和事务守恒在“哪一个文件、哪一层代码”被强制拦截。

### 3. 铁匠（Core SWE / 平台核心研发）
- **Palantir 作战力量**: **Dev (底座研发与静态编译器守卫)** — “Devs create”。
- **唯一主责**: 平台底层核心逻辑、编译器 AST 静态守卫、复杂通用事务流转，确保错误在编译期就被工具硬拦截，不靠人工记忆（“One capability, many customers”）。
- **独占产出**:
  - `增量编译 0 报错的代码基线` (`tsc --noEmit` 100% 通过)；
  - `模块单向依赖与静态守卫用例` (如 `check-token-gates`、`guard-high-order-invariants`)；
  - `核心事务与状态机底层流转实现`。
- **严禁行为 (Anti-Patterns)**:
  - 严禁使用宽松类型（如将强枚举降级为 `string`，或使用 `any` 穿透）；
  - 严禁空 `catch {}` 块吞掉异常。
- **协同交接契约**: 移交给门神交付前，必须提供严密的类型定义与接口契约声明。

### 4. 门神（FDSE / 前线部署工程师）
- **Palantir 作战力量**: **Delta (前线全栈交付第一责任人)** — “Deltas build / Exec”。
- **唯一主责**: 亲自编写全栈业务功能、防御性 UI，负责端到端在真实环境（Android 原生模拟器 / Web 真实浏览器）中 100% 跑通闭环（“One customer, many capabilities”）。
- **独占产出**:
  - `带时间戳的真机模拟器截图与操作视频存证`；
  - `页面四态 (Loading/Data/Empty/Error) 状态机覆盖证据`；
  - `防物理遮挡与键盘顶起布局实现`。
- **严禁行为 (Anti-Patterns)**:
  - 严禁只测默认分支（切到空数据或异常态就白屏）；
  - 严禁出现假按钮（`onClick` 为空或仅 `console.log`）。
- **协同交接契约**: 移交给百晓生 (DS) 验收前，必须保证所有主交互在真机上均可单手闭环点击。

### 5. 兑底渊（PRE-SRE / 产品可靠性专家）
- **Palantir 作战力量**: **Dev (平台基础设施可靠性与发布自动化)** — “Devs scale”。
- **唯一主责**: 确保“测过的东西就是发布的东西”；负责环境版本指纹对齐、不可变制品管理、发布后拨测与自动化守卫反向传播（Palantir Apollo 级自动化发布管网）。
- **独占产出**:
  - `7 处版本号一致性核验证明`；
  - `生产发布日志与健康拨测探针报告`；
  - `秒级应急回滚 SOP 与自动化防退化守卫脚本`。
- **严禁行为 (Anti-Patterns)**:
  - 严禁在服务器上就地临时改代码（制品必须不可变）；
  - 严禁版本指纹不一致时放行发版（持有一票否决权）。
- **协同交接契约**: 投产前必须出具制品不可变哈希与双人会签单。

### 6. 百晓生（DS / 部署战略与业务方案专家）
- **Palantir 作战力量**: **Echo (业务方案与真实 Outcome 验收)** — “Echos win / Verify”。
- **唯一主责**: 【用户视角主审官】（Palantir 原生 Deployment Strategist 孪生）。不看代码实现，只当最终用户；把业务旅程从头走到底，捕获所有“技术跑通但业务荒谬”的深层缺陷，持有投产一票否决权。
- **独占产出**:
  - `端到端业务旅程通断验收报告`；
  - `死交互与假按钮现场退单清单`；
  - `极简两字按钮与业务语义合规判定书`。
- **严禁行为 (Anti-Patterns)**:
  - 严禁妥协放行业务走不通的半成品（如流程能提交但下游根本无法审批处理）；
  - 严禁在测试中做任何“这里跳过”的技术脑补与心智补偿。
- **协同交接契约**: 只有百晓生签字确认业务 Outcome 达成，任务才算真正完成。

## 四、 如何将 Coolie 工坊 Agent 治理经验注入下游重型业务模板 (`ruoyi-all-next`)？

`ruoyi-all-next` 是面向重型业务（ERP、MES、供应链、金融结算）的工程开发底座，必须天然内置 Coolie 工坊的 Agent 管理能力：

1. **内置 NPC 复合对象管理模块**：
   - 借鉴 Coolie 的 `agents` 数据字典，在 `ruoyi-all-next` 中构建数字员工编制中心，为业务系统提供“审批 Agent”、“对账 Agent”、“巡检 Agent”等标准实体；
2. **内置配额与预算硬停熔断机制**：
   - 业务系统调用外部大模型或高耗算力时，必须通过 `AgentQuotaService` 进行月度预算硬停截断，杜绝生产资费失控；
3. **内置任务派单收据与事件源日志**：
   - 任何由 Agent 触发的业务变动，强制生成不可篡改的 Execution Receipt，并记入业务审计日志；
4. **内置量化 KPI 态势仪表盘**：
   - 将上述 6 大员工的 KPI 采集逻辑封装为标准看板组件，让交付公司负责人随时穿透查看每一个 Agent 的人效比与履约质量！
