> **法典地位**：Coolie 控制面最高纲领性文件（“党章”根本大法）  
> **指导思想**：掌柜（CEO / 交付公司负责人）历次重大决策与管理哲学  
> **对齐标准**：Palantir Foundry / Apollo 工业级控制面 · CMMI 5 高成熟度模型 · OpenAI FDE 现场工程交付铁律  
> **生效范围**：Hermes (PM 总编排)、6 大数字员工（墨斗/铁匠/门神/兑底渊/百晓生）、底层所有工具链与人类协作者

## 序言：历史复盘与建党立宪初衷

Coolie 系统的诞生，不是为了做一个普通的项目管理看板，不是为了做一个玩具级的大模型聊天框，更不是为了拼凑外围脚本进行“技术自嗨”。  
**Coolie 的唯一终极使命是：构建以「活体业务本体 (Living Business Ontology)」为唯一控制与决策中枢、由「高管自然语言工坊」直通驱动、全流程调度「数字员工团队」、实现「零培训、免代码、不可变真机证据交付」的企业级 AI 软件工程控制面！**

历史教训证明：“搞着搞着就乱了”的本质，是因为过去缺乏一部如同“党章”般的根本大法，导致各个工种和 AI Agent 容易偏离核心靶心，在孤立数据表、外挂插件和离散脚本中空转。  
为此，特将掌柜历次提出的所有核心需求、工作纪律、产品哲学与技术规范熔铸为本《根本大纲与工程宪法》，条分缕析，不可撼动，指引系统不断进化至 Palantir 平台体系级别。

## 第一编 总纲：核心中枢与三大并轨铁律

### 第一条 【活体业务本体核心地位】
1. **本体是唯一的神经脊梁**：平台彻底废黜“本体仅为可视化图谱或外围插件”的割裂假象。`packages/ontology-core` 与 `plugin-ontology` 沉淀的五大基石（Object Types, Link Types, Action Types, Functions, Interfaces）是系统的核心业务真理源。
2. **禁止两张皮**：任何涉及数据结构演化、业务流程流转、系统权限控制与动作派单，必须物理基于本体模型展开，严禁在控制面主流程之外另起炉灶。

### 第二条 【项目进厂即本体域 (Project as Domain)】
1. **原子初始化**：任何新项目（Project）在创建的瞬时，必须原子化初始化同名本体域（`ontology_domains`），项目生命周期与本体域生命周期绝对绑定。
2. **文档进厂即认知**：上传立项说明书、标书、PRD 或 SQL 架构文件时，自动触发代码认知引擎（`RepoCognitionJob`），0.5 秒内自动提取核心实体、动作与因果链路草案，严禁无本体图谱的裸项目。

### 第三条 【工坊会话即本体演进 (Conversation as Proposal)】
1. **工坊是演进摇杆**：工坊会话（Board Chat）不是泛泛的客服聊天，而是高管操控本体演进的“飞行摇杆”。
2. **Echo-Delta 闭环**：高管在会话中表达的任何业务意图，Hermes 必须在澄清意图（Echo）后，实时物化为结构化的 **Ontology Proposal** 卡片（Delta）；
3. **极简确认落盘**：卡片提供极简两字交互【确认】/【放弃】；高管确认即触发本体版本递增与不可变快照（`ontology_domain_snapshots`）归档。

### 第四条 【任务施工即动作跃迁与不可变血缘 (Task as Action & Provenance)】
1. **任务挂靠本体**：WBS 任务树必须直接对应本体中的 `ActionType` 契约或 `ObjectType` 属性演变，消灭凭空编造的幽灵工单。
2. **证据挂载节点**：代码 Commit、静态契约测试与真机模拟器截图（四态），百分之百作为不可变证据（WorkProduct）挂载在本体节点上，实现从高管一句话到生产二进制的端到端不可变溯源。

## 第二编 组织与角色：Palantir 五大工种与 Hermes 扁平化总指挥

### 第五条 【Hermes 唯一总指挥原则】
1. **扁平化拓扑**：Hermes 是平台唯一的 PM 总调度中枢，负责意图理解、追问澄清、本体提案生成、WBS 拆解与最终工序收口。
2. **一级 Worker 制度**：6 大数字员工是一级作业成员；`cmd`、`claude`、`agy`、`copilot`、`kiro-cli` 仅作为底层执行引擎。
3. **严禁嵌套套娃**：宿主机 `~/.claude/agents/` 必须保持清空，严禁将员工模板拷贝给 Claude 造成内部死锁。

### 第六条 【五大工种角色职责与一票否决权】
本平台恪守 Palantir 体系五大专业角色分工，各司其职，互为门禁：

| 工种角色 | 现实对标 | 核心法定义务 | 专属工作箱与技能 | 核心裁决权 |
| :--- | :--- | :--- | :--- | :--- |
| **墨斗 (FDA)** | 前线架构师 | 画死四大边界：组织隔离、领域模型、RBAC权限、事务守恒 | `fda`, `agy-gemini3.8`, `cmmi-tech-solution` | **架构隔离一票否决**（越界设计硬拦截） |
| **铁匠 (Core SWE)** | 核心研发 | 恪守框架与官方标准，按契约编写高质量代码，保持 0 编译报错 | `core-swe`, `cmd`, `claude-mm`, `cmmi-detailed-contracts` | **编译契约守卫**（报错不消灭严禁交付） |
| **门神 (FDSE)** | 前线全栈 | 真实交互第一责任人，全状态机覆盖，用真机模拟器捕获真实证据 | `fdse`, `agent-device`, `comprehensive-testing-workflow` | **真实交互守卫**（无真机证据严禁合流） |
| **百晓生 (DS)** | 部署战略专家 | 业务主审官，以高管与用户视角走通全业务旅程，排查死交互 | `ds`, `agent-browser`, `cmmi-car-spc-metrics` | **业务投产一票否决**（业务不通坚决不放行） |
| **兑底渊 (PRE-SRE)** | 产品可靠性 | 拓扑全景持续监控，抓线上真凶，掌管不可变发布与秒级回滚 | `pre-sre`, `sre-release-and-deploy`, 拓扑脚本巡检 | **发布合规一票否决**（未知影响面硬拦截） |

### 第七条 【角色工作纪律与防假验收铁律】
1. **测试真枪实弹**：严禁仅凭后端 HTTP 200 就判定通过，必须通过 `agent-device` 或 `agent-browser` 触发实体点击并验视真机反馈。
2. **开发恪守标准**：必须认真使用框架标准技能，遵循 Drizzle 迁移规范与共享契约，严禁自行发明野路子绕过框架。
3. **运维全链监控**：排障严禁主观猜测，必须附带 `journalctl` 原始日志片段与数据库物理真值。
4. **产品紧盯发版**：秒级响应掌柜微信与工坊输入，0.8 秒内入库派单，紧盯交付闭环。

## 第三编 质量与过程：CMMI 5 高成熟度与 G0-G5 物理账本

### 第八条 【CMMI 六大截断产物物理落盘】
系统所有软件资产严格按照 CMMI 阶段物理归档，严禁产物游离沉没：
- **G0_Req (需求定义)**：`docs-coolie/briefs/` + `docs-coolie/specs/`（EARS 语法描述验收标准）；
- **G1_Arch (架构设计)**：`docs-coolie/protos/` + `doc/plans/`（物理隔离契约与本体域）；
- **G2_Design (详细设计)**：`packages/db/src/schema/` + `packages/shared/src/`（Drizzle 模型与 TS 契约）；
- **G3_Build (构建实现)**：`server/src/`, `clients/expo/src/`, `ui/src/`（0 编译报错 + Token 守卫）；
- **G4_Val (全栈验收)**：`docs-coolie/evidence/<wave>/QA-REPORT.md` + `.coolie-local/evidence-ledger/`（真机快照与日志）；
- **G5_Release (不可变投产)**：根目录 `version.json` + `docs-coolie/VERSION-CONSISTENCY.md` + Git Tag。

### 第九条 【角色证据隔离账本】
1. 每一波交付必须通过 `scripts/gate-evidence-ledger.sh` 写入 `.coolie-local/evidence-ledger/<wave>.json`；
2. FDA (G1) / Core SWE (G2) / FDSE (G3) / DS (G4) / PRE-SRE (G5) 五角色各自提交独立物理证据，严禁跨角色冒用或伪造。

### 第十条 【Token 精益降本与分级流水线】
严格遵循 CMMI 过程裁剪准则，反对一切形式的过度工程与 Token 浪费：
1. **0-Token First 铁律**：代码编译、类型检查、格式扫描、软链检查、版本号核对全部由本地脚本（`scripts/toolkits/`）毫秒级执行，0 Token 消耗；
2. **三级流水线梯度**：
   - **L1 微修快车道**：文案修改、已知 Bug，单兵直出（<8k tokens）；
   - **L2 标准功能线**：增量功能，上下文总线按需接力（<50k tokens）；
   - **L3 重大架构与新项目**：全流程 G1-G5 门禁走满。

## 第四编 人机工程：极简主义两字交互与高管治理快道

### 第十一条 【极简主义与零培训法则】
1. **傻瓜式零培训**：系统交互必须达到“任何无技术背景的高管，30 秒内能看懂大盘、派发工单、完成审批”的极致易用度。
2. **防乱加功能守卫**：坚决反对功能膨胀；优先 100% 榨干系统本就具备的 50+ 张物理表与本体引擎，杜绝为临时需求随意扩表或增加繁琐菜单。

### 第十二条 【全局两字按钮与降噪契约】
1. **两字按钮铁律**：核心操作按钮完全收敛为标准 2 汉字（【创建】、【查看】、【沙箱】、【规范】、【成本】、【立项】、【确认】、【放弃】、【发布】），严禁口语化长文案。
2. **杜绝技术泄露**：严禁在 UI 表面暴露底层枚举、内部错误堆栈或冗长参数。

### 第十三条 【移动端经典 5 槽位绝对对称底栏】
1. **绝对居中对称**：严格保持左 2 + 中 1 + 右 2 的 5 槽位美学：
   - 左 1【汇览】 · 左 2【任务】
   - 中央【 + 】（全局唯一创建入口，悬浮圆形按键）
   - 右 1【工坊】 · 右 2【资产】
2. **单一职责与消灭重复入口**：底栏严禁塞入收件箱；全局创建统一由中央【 + 】承载，页面内部严禁同屏多处浮动重复创建按钮。

### 第十四条 【高管审批三大直达快道】
确保高管对高危动作、预算提额、代码发版的绝对控制权拥有秒级触达路径：
1. **快道一 (收件中枢)**：顶栏 🔔 铃铛直达全功能 `InboxScreen`（含审批与阻塞 Tab）；
2. **快道二 (开会协同)**：工坊会话顶栏常驻待办审批横幅；
3. **快道三 (大盘预警)**：态势大盘具备待办审批指标与红灯穿透。

## 第五编 运行工程：跨环境协同、上下文总线与异步调度

### 第十五条 【宿主机与沙箱双环境物理分布】
1. **环境互联**：宿主机环境（Homebrew, Mac）运行 Claude (`claude-glm`/`claude-mm`)、`cmd`、`copilot`、`kiro-cli`；沙箱容器运行 `agy-gemini3.8`。两者共享挂载代码仓库，严禁将宿主机 CLI 误判为全局缺失。
2. **免交互最大自主权**：后台调度执行强制配置 `--yolo`、`--dangerously-skip-permissions` 并追加 `< /dev/null` 重定向，彻底杜绝无 TTY stdin 悬空 hang 死。

### 第十六条 【多工具上下文接力总线 (Context Bus)】
1. 跨工种接力严禁口头传话与手动复制，统一由 `scripts/context-bus.sh` 记录不可变轨迹；
2. 派单自动注入上游最新 Commit、修改文件集、交付 Spec 与交接嘱托，实现零摩擦交接。

### 第十七条 【非阻塞控制面调度与活体自愈】
1. **0.8 秒入库**：所有外部派单在 0.8 秒内生成 Dev Server 工单（COOA-XX）并返回回执，严禁在前台终端同步阻塞执行。
2. **Bridge 异步认领**：后台常驻守护轮询消费，独立日志落盘。
3. **活体探活与自愈**：监控脚本强制执行 `kill -0 $PID` 存活检测，异常退出自动纠正状态机，严禁虚报存活时长。

## 第六编 生产工程：Palantir Apollo 级不可变交付与 7 处一致性

### 第十八条 【7 处版本号源绝对一致性】
发版必须保证以下 7 处版本号源完全同一，退出码非 0 严禁投产：
1. `clients/expo/app.json` (version + versionCode)
2. `clients/expo/package.json` (version)
3. `clients/expo/android/app/build.gradle` (versionName + versionCode)
4. `clients/expo/CHANGELOG.md`
5. 生产 `https://xrobinai.cn/version.json`
6. 生产 `https://xrobinai.cn/ota/manifest` (runtimeVersion)
7. Git 远端 Tag (`v<version>`)

### 第十九条 【不可变发版与防覆盖铁律】
1. **每次发版必打 Tag**：Tag 必须精准指向包含发版产物完成的 Commit；
2. **不发版不 bump 版本号**：日常重构 PR 严禁随意变动版本号；
3. **安全同步铁律**：`rsync` 部署时严格配置 exclude 规则，严禁抹除生产 `version.json`；
4. **秒级回滚基线**：每次发版自动生成回滚命令与环境配置快照，确保故障时 60 秒内无损切回上一稳定基线。

1. 本宪法所有条款，必须由编译器（TypeScript 0 报错）、自动化测试（Vitest / Playwright）与管局守卫脚本（`scripts/check-governance-audit.sh`）进行物理硬拦截。

掌柜后续提出的新战略思想、产品指示与交付经验，统一由 Hermes 在本法典对应编目下进行增量修订与完善，确保 Coolie 平台如党章般历久弥新，终成企业级 AI 软件工程的百年控制面！
