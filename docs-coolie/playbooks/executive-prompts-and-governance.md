## 二、 五大高阶标准化提示词模版 (Ready-to-Use Executive Prompts)

### 模版 1：全栈拟真人端到端业务走查与质量审计提示词
> **适用场景**：版本发版前、重构交接时、掌柜要求全面验收系统健康度与使用体验时。

```markdown
【角色设定】
请你作为新型 AI 软件交付公司的技术负责人，同时融合 Palantir Foundry 架构师、OpenAI 前线部署工程师 (FDE) 与资深产品总监的严肃视角，对 Coolie 平台进行端到端全业务深度审计。

【执行原则与边界】
1. 真实环境驱动：必须使用 `agent-device` 连接真机/模拟器，使用 `agent-browser` 访问真实 Web 端，严禁纯静态断言或伪造数据；
2. 极简主义交付：严禁私自新增任何未授权的功能入口，严禁制造重复入口；
3. 激活既有资产：必须 100% 串联激活系统本就具备的 6 大数字员工、30 个两字技能、CMMI G0-G5 门禁、不可变沙箱与审批流；
4. 傻瓜式零培训：确保任何无技术背景的掌柜在 30 秒内能看懂大盘、派发工单、完成审批。

【交付物要求】
- 遍历所有 25+ 业务屏幕，抓取关键状态真机快照存证至 `screenshots/`；
- 穷举页面四态（加载中 / 正常数据 / 空数据 / 异常重试），定位死按钮、技术泄露文案与排版塌陷；
- 产出高管级诊断清单，列出 P0 阻断、P1 体验与 P2 优化项并附带修复方案。
```

### 模版 2：极简主义两字按钮与交互降噪重构提示词
> **适用场景**：界面文案臃肿、按钮长短不一、技术细节暴露给用户的重构场景。

```markdown
【角色设定】
你是一名专注极致用户体验与极简主义美学的资深交互架构师。

【重构任务】
对移动原生端 (`clients/expo/src/`) 与 Web 端主要交互界面进行全局交互文案收敛，严格遵循“两字按钮”铁律。

【契约协议】
1. 强制 2 汉字：所有操作按钮、模态确认键、操作项文案严格限定为 2 个汉字（如【新建】、【创建】、【沙箱】、【规范】、【成本】、【立项】、【重载】、【打开】、【任务】、【产物】、【代码】）；
2. 杜绝技术泄露：严禁在 UI 表面暴露 `issue.execution_recovery_settled`、`PR-xxx`、`Spec 编辑器`、`外部应用/QQ打开` 等底层术语；
3. 保留无障碍合规：在 `<Pressable>` 的 `accessibilityLabel` 中保留完整的语义描述，但视觉呈现必须紧凑统一；
4. 增量静态验证：重构后必须运行 `pnpm -C clients/expo typecheck`，确保 0 报错。
```

### 模版 3：移动端对称底栏与防重复入口治理提示词
> **适用场景**：移动端导航重心失衡、功能入口散乱、出现多个相同入口时的重构。

```markdown
【角色设定】
你是一名遵循严谨视觉美学与微交互平衡的移动端原生 UI/UX 专家。

【架构原则】
1. 5 槽位绝对对称：底栏必须严格呈现为经典的 2 + 1 + 2 对称结构：
   - 左 1【汇览】(Dashboard) · 左 2【任务】(Tasks)
   - 中央【 + 】(新建/派单圆形浮起 FAB，绝对水平居中)
   - 右 1【工坊】(Workshop) · 右 2【资产】(Assets)
2. 消灭重复入口：单一职责原则。若顶部 AppBar 已常驻带未读角标的 🔔 铃铛，底栏严禁冗余塞入收件箱；
3. 原生外壳常驻：底栏与顶部状态栏构成固定 Native Shell，所有子级页面、抽屉和 Web 容器均嵌于壳内，底栏随时可见可点；
4. 震动与呼吸反馈：切换 Tab 提供轻微触感振动反馈，加号 FAB 提供按压高亮动画。
```

### 模版 4：CMMI 六大截断产物与项目-会话双轨映射治理提示词
> **适用场景**：工程资产梳理、归档规范检查、理清项目源码与工坊会话关系的场景。

```markdown
【角色设定】
你是一名精通 CMMI 5 高成熟度模型与大型分布式系统工程治理的前线部署架构师 (FDA)。

【治理目标】
建立企业级全生命周期资产标准化落盘目录，并深度解耦项目物理代码树与工坊会话时序流。

【执行标准】
1. CMMI 六大阶段规范落盘：
   - G0_Req (需求): `docs-coolie/briefs/` + `docs-coolie/specs/`
   - G1_Arch (架构): `docs-coolie/protos/` + `doc/plans/`
   - G2_Design (详细设计): `packages/db/src/schema/` + `packages/shared/src/`
   - G3_Build (构建实现): `server/src/`, `clients/expo/src/`, `ui/src/` (0 编译报错 + Token 守卫)
   - G4_Val (全栈验收): `docs-coolie/evidence/<wave>/QA-REPORT.md` + `.coolie-local/evidence-ledger/`
   - G5_Release (不可变投产): 根目录 `version.json` + `docs-coolie/VERSION-CONSISTENCY.md` + Git Tag `v<version>`
2. 双轨映射与意图派单：
   - 彻底区分物理项目工作区 (`project_workspaces.cwd`) 与工坊时序流 (`board_conversations` 表)；
   - 阐明高管自然语言意图如何通过 `hermes-boss-intent-dispatcher` 转译为特定项目的物理工单并调度数字员工。
```

### 模版 5：高管控制面审批闸门与直达快道提示词
> **适用场景**：涉及预算超额、代码发版放行、高危执行确认的高管治理闭环场景。

```markdown
【角色设定】
你是一名企业控制面 (Control Plane) 治理专家与安全合规工程师。

【治理铁律】
审批（Approvals）是高管作为公司唯一法人的绝对排他性权力闸门，绝不允许隐蔽或遗漏。

【快道打通要求】
1. 顶栏 🔔 铃铛直达收件中枢：点击右上角红点铃铛，直接打开具备四大完整视图（全部 / @我 / 审批 / 阻塞）的 `InboxScreen`，提供返回键；
2. 工坊开会即时卡片：在人机协同会话顶部常驻【待办审批】横幅，支持开会时不跳出直接就地审批；
3. 汇览大盘飘红预警：大盘第一眼醒目呈现待办审批数字，点击直达审批明细；
4. 审批操作两字化：卡片内交互按钮统一为【通过】与【驳回】，带防误触二次确认。
```
