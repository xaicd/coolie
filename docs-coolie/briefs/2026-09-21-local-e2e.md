# Brief: Local E2E harness for Coolie App via agent-device

SPEC (read first): `docs-coolie/specs/2026-09-21-local-e2e-harness.md`
Repo: `~/workspace/xaicd/coolie` (branch `main`)

## Goal

Give the PM a **local, one-command E2E acceptance harness** for the Coolie app on this
Mac. No CI. No cloud device farm. Use `agent-device` (already installed at
`/opt/homebrew/bin/agent-device`).

## Environment facts (already verified by PM — do not re-investigate from scratch)

- `agent-device` is installed. `agent-device devices` returns empty (no simulators,
  no connected android device).
- iOS simulators are NOT available: `xcrun simctl` is missing (only CommandLineTools
  installed, no full Xcode). Do not try to install Xcode.
- Android SDK lives at `/Users/mac/android-sdk` and has build-tools, platform-tools,
  ndk, platforms — but NO `emulator/` and NO `system-images/`. `adb devices` is empty.
- `agent-device web doctor` currently fails with
  `TOOL_MISSING: Managed web browser backend is not installed`.
- `clients/expo/package.json` has a `"web": "expo start --web"` script but does NOT
  declare `react-native-web` / `react-dom`.
- An old replay script exists at `clients/expo/replays/coolie-flow.ad` on branch
  `agent-device/e2e-ios` and it opens the WRONG app (`cloud.coolie.app`). Do not trust it;
  rewrite for local use.

## Required deliverables

1. **Install the web backend**: run `agent-device web setup`, then prove
   `agent-device web doctor` reports healthy. Paste both outputs.

2. **`scripts/e2e-local.sh`** (new): one-command local acceptance run.
   - Preflight: check `http://localhost:3100/api/health`. If not up, either start the
     local stack (`pnpm dev`, background) or fail loudly with the exact start command.
     Do NOT silently continue.
   - Run one or more agent-device replays with `--platform web`.
   - Print an assertion summary (passed/failed counts) and the absolute path of every
     evidence file.
   - Exit non-zero on any assertion failure.

3. **Replay scripts** under `clients/expo/replays/` targeting LOCAL urls only
   (`http://localhost:3100` and/or the Expo web dev server). Cover these 3 flows with
   REAL assertions (not bare screenshots):
   - **Ontology page**: domain list renders; assert domain card count >= 7.
   - **Tasks page**: task list renders and is non-empty (or an explicit empty-state
     string is present).
   - **Board chat**: send one text message and assert a REPLY ARRIVES (reply bubble text
     length > 0 / streaming chunk observed). If the local stack cannot produce a reply
     within the timeout, that is a FINDING — record it as a real failure with evidence,
     do not weaken the assertion to make it pass.

4. **Evidence**: screenshots into `clients/expo/replays/evidence/` (create the dir, add a
   `.gitkeep`). Evidence must be committed.

5. **`docs-coolie/LOCAL-E2E.md`** (new): how to run it, what it covers, what it does NOT
   cover, and known limitations.

6. **Proof of assertion integrity**: pick ONE assertion, deliberately make it false
   (e.g. expect 99 domains), show the run FAILS with the right message, then revert.
   Paste both runs.
