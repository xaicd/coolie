## 详细专家评审专章

### 一、 Palantir Foundry 控制面专家评审专章
- **评审人**：Palantir Apollo & Foundry 架构资深专家
- **核心论断**：
  *“Coolie 的核心价值在于它是 AI 员工的控制面（Control Plane），而不是玩具聊天室。既然是控制面，数据血缘与治理闸门就是生命线。”*
- **深度挑刺**：
  1. **本体论（Ontology）深度不足**：目前的业务本体（`OntologyDomainListScreen`）只停留在查看域、对象与图谱，缺乏对真实业务数据（如工单、代码、制品）的逆向同步验证。
  2. **物理数据隔离**：虽然全系统遵守了 `company_id` 物理隔离，但缺少针对 SQL 查询构造器的编译器插件，存在新人误写无 `company_id` 裸查询的风险。
- **改进落地规范**：
  - 编写 Drizzle 查询拦截器，凡是没有携带 `company_id` 过滤条件的查询在开发模式下直接抛出 `CompanyScopeViolationError`。

---

### 二、 OpenAI / Anthropic 前线部署工程师 (FDE) 评审专章
- **评审人**：大型语言模型生产级落地与 Multi-Agent 架构工程师
- **核心论断**：
  *“数字员工最怕的不是任务难，而是‘指令模糊’与‘上下文失真’。把长对话原样扔给模型是极度业余的做法。”*
- **深度挑刺**：
  1. **上下文失真风险**：工坊（Board-Chat）目前对话越来越长，直接全量序列化会带来 Token 浪费并稀释核心指令。
  2. **歧义派单吞吐问题**：当老板说了一句非常简短的口语（如“修一下登录”），意图分发器若直接派单给铁匠，铁匠可能会盲目猜测到底是修原生登录还是 Web 容器登录。
- **改进落地规范**：
  - 在分发器中植入**澄清阻断（Clarification Gate）**：凡是意图置信度低于 0.85 的模糊需求，自动就地返回带有 2~3 个选项的高管确认卡，高管点击选项后立即精准派发。

### 三、 Linear / Superhuman 极简交互设计专家评审专章
- **评审人**：硅谷一线顶级生产力工具交互设计总监
- **核心论断**：
  *“在移动端上，每个多余的汉字都是对用户注意力的粗暴抢劫。极致的工具必须做到无感、克制、像流水一样顺畅。”*
- **深度挑刺**：
  1. **底栏 5 键对称规范是正确的**：消灭收件箱并保持 2+1+2 对称是顶级设计语言的体现。但需要注意屏幕物理下边缘的安全区域（SafeArea），在全面屏设备上底部微间距需精确到 pt。
  2. **两字按钮的彻底性**：不仅移动端要执行，Web 端所有的提交、确认、重置按钮也必须完全收敛为 2 汉字（如【发布】、【保存】、【同步】），坚决消灭“点击确认提交表单”等冗长文案。
- **改进落地规范**：
  - 保持 `pnpm check:governance` 每日门禁常态化巡检，发现 >2 汉字按钮直接打断构建。

### 四、 CMMI 5 质量工程与过程改进专家评审专章
- **评审人**：SEI CMMI 高成熟度主任评估师 (Lead Appraiser)
- **核心论断**：
  *“软件交付的第一法则：不可逆的证据链。没有测试存证的交付，在审计面前等同于不存在。”*
- **深度挑刺**：
  1. **需求追溯矩阵（RTM）断链风险**：`docs-coolie/briefs/` 中的需求如果变成了代码，必须有明确的 Git Commit Hash 与其绑定。
  2. **SPC 过程控制未全面覆盖**：CMMI 5 强调统计过程控制（SPC），目前已有工单耗时监控，但对缺陷率控制图的波动预警仍需更直观的大盘呈现。
- **改进落地规范**：
  - 将 G0-G5 的每个阶段流转记录强制写入 `.coolie-local/evidence-ledger/<wave>.json`，五角色不可借用，机器验签防篡改。

### 五、 Google SRE / 基础设施架构师评审专章
- **评审人**：分布式云原生可靠性与混沌工程架构总监
- **核心论断**：
  *“系统的可靠性不是祈祷出来的，是预设所有东西都会挂的前提下设计出来的。”*
- **深度挑刺**：
  1. **幽灵任务自愈**：团队状态脚本检测到死进程时修正为 `failed` 是必要的，但需要向高管推送自愈告警，说明是 OOM 还是超时。
  2. **OTA 缓存陷阱防范**：必须严格保证生产 Caddy 路由不对 `/ota/manifest` 注入 HTML 兜底，否则真机将陷入静默白屏。
- **改进落地规范**：
  - 固化 `scripts/VERSION-CONSISTENCY-CHECK.sh` 与 `scripts/check-governance-audit.mjs`，在每次部署前执行健康拨测。

### 六、 AI 交付公司创始人兼 CEO 评审专章
- **评审人**：现代高科技 AI 软件交付公司创始人兼 CEO
- **核心论断**：
  *“高管的核心职责是两件事：把握战略方向与看紧钱袋子。审批权不可旁落，ROI 必须透明。”*
- **深度挑刺**：
  1. **审批通道直达度**：顶栏 🔔 铃铛直达收件箱和工坊常驻横幅已经解决了找审批难的问题，但审批单内的成本预测（“批准此申请预计增加多少 Token / 耗时”）应一并展示。
  2. **交付周期确定性**：高管关心“这个功能什么时候能上线”，任务看板必须直观标识预计完成时间与阻断风险。
- **改进落地规范**：
  - 在审批模态框直接显示预算增量预估，让高管拥有清晰的成本直觉。
