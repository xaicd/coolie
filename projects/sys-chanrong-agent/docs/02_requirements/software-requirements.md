# 产融商业保理与供应链金融智能体系统 软件需求规格说明书 (SRS)

> **所属业务系统**: 产融商业保理与供应链金融智能体系统 (`SYS_CHANRONG_AGENT`)
> **所属本体域**: `enterprise-core`
> **技术栈**: `node / react / python-vision / docker`
> **基线版本**: `v1.0.0-BASELINE`
> **编制依据**: 《某公司产融智能体应用系统集成服务项目 技术规范书》
> **规范**: IEEE 29148 / EARS 五态句式；每条需求可直接转译为测试断言

## 1. 项目背景与交付目标

为甲方（国信产融）构建面向**保理与供应链金融**业务的智能化产融协同与智能体应用系统。
通过多智能体中枢、多模态单证智能抽取（OCR）、风控规则引擎与企业本体图谱，实现产融业务全流程智能化。

核心目标：
1. **企业本体画像与数字资产沉淀**：建立核心企业、链属企业的企业数字本体画像。
2. **多模态单证秒级结构化抽取**：增值税发票、财务三表（资产负债表/利润表/现金流量表）、贸易合同、银行流水的自动 OCR 与逻辑勾稽。
3. **产融智能体集群编排**：政策问答、风控初审、额度测算、预警监控智能体。
4. **双端业务协同**：PC 运营控制台 + 移动端掌上产融门户，支持多终端审批流转。
5. **外部系统集成**：标准化适配器挂接甲方门户 SSO、金税发票查验、工商/司法/征信数据接口。

## 2. EARS 功能需求清单

### 2.1 企业画像与档案管理
- **REQ-CR-001 [企业本体档案]**：**While** 系统处于正常运行状态，**the** system **SHALL** 维护企业统一信用代码、组织架构树、产业链上下游关联合同关系，并支持多法人实体的物理逻辑隔离。
- **REQ-CR-002 [征信与外部数据同步]**：**When** 操作员或定时任务发起企业资信刷新，**the** system **SHALL** 自动调用外部征信与工商接口，解析并持久化企业经营异常、涉诉信息及行政处罚记录。

### 2.2 多模态单证智能抽取与校验
- **REQ-CR-003 [发票智能识别与验真]**：**When** 用户上传增值税发票（PDF/JPG/PNG），**the** system **SHALL** 完成发票代码、号码、开票日期、金额、税额、销方及买方信息的结构化抽取，并校验金额与明细的数学求和一致性。
- **REQ-CR-004 [财报三表勾稽与指标计算]**：**When** 用户导入企业近三年财务报表，**the** system **SHALL** 自动提取资产负债表与利润表核心科目，计算资产负债率、流动比率、速动比率及营业利润率；**If** 报表左右平衡公式不满足，**then** the system **SHALL** 标红告警。
- **REQ-CR-005 [贸易合同结构化核验]**：**When** 上传贸易采购合同文档，**the** system **SHALL** 抽取买卖双方、交易标的、合同总金额、支付账期、违约责任条款，并比对合同金额与关联发票总金额的匹配度。

### 2.3 产融智能体中枢与问答
- **REQ-CR-006 [政策法规与产品问答 Agent]**：**Where** 用户在 PC 端或移动端向「政策咨询智能体」提问，**the** system **SHALL** 检索本地向量知识库，返回附带原文出处及依据条款的结构化回答。
- **REQ-CR-007 [风控初审与合规审查 Agent]**：**When** 融资申请进入初审阶段，**the** system **SHALL** 触发「风控审查智能体」比对申请企业资信、发票真伪、贸易背景真实性及负面舆情，出具《风控初审报告草稿》。

### 2.4 融资业务全流程流转
- **REQ-CR-008 [授信申请与额度测算]**：**When** 链属企业提交融资意向，**the** system **SHALL** 依据可配置风控规则（LiteFlow 外置规则）结合近 12 个月开票总额、纳税等级及历史履约率测算建议授信额度。
- **REQ-CR-009 [多级审批与状态机转移]**：**If** 申请额度超过预设阈值（例如 500 万元），**then** the system **SHALL** 自动路由至双人会签会审流程；在所有审批节点未完成签字之前，**the** system **SHALL** 锁定该申请，禁止流转至放款状态。

### 2.5 外部系统集成与安全防护
- **REQ-CR-010 [甲方门户 SSO 集成]**：**When** 用户从甲方现有门户系统跳转时，**the** system **SHALL** 通过 OAuth2/JWT 令牌验证用户身份，并自动完成角色权限映射，不得要求用户重复输入密码。
- **REQ-CR-011 [审计跟踪与防篡改日志]**：**While** 任何用户或智能体执行状态变更、额度调整或数据导出操作，**the** system **SHALL** 自动记录不可篡改的审计日志（含操作人、时间、源 IP、变更前值、变更后值）。
- **REQ-CR-012 [离线私有化与 License 授权锁]**：**When** 系统在私有服务器启动时，**the** system **SHALL** 校验本地硬件指纹（MAC/CPU/主板序列号）及离线 License 有效期；**If** 签名校验失败或已过期，**then** the system **SHALL** 拒绝提供业务服务并记录越权启动告警。

## 5. 验收与确认准则

1. 需求与用例覆盖率必须达到 100%。
2. 所有需求项为结构化可判定状态，符合 IEEE 29148。
3. 任何需求变更必须经 CCB 双人签名批准。
4. 无效量化承诺（无实测证据的性能数字）一律改为相对表述，不得随标书作为可罚承诺。
