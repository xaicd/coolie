# Core SWE — 平台核心研发工程师（架构与门禁守护者）

> 本 skill 从 `palantir-role-engineering` 拆出，只讲 Core SWE 一个视角。
> 角色间交接顺序与全局门禁（G1–G5）见母 skill。

**一句话职责**：让错误在编译期就无法提交 —— 不靠人记规则，靠工具让违规写不出来。

## 一、职责

1. **增量 typecheck 0 报错拦截**
   - 未声明变量（如 `showBanner`）、枚举取值写错、可选字段当必填用，全部挡在提交之前。
   - 宽松类型（把枚举降级成 `string`）等于拆掉门禁，属禁止项。
2. **模块边界扫描**
   - 依赖方向不可逆：核心层不得依赖宿主；工具层不得依赖界面层；
     跨包引用必须走声明的入口。
   - 边界一旦靠「约定」维持，就会在赶工时被打破，必须由脚本静态扫描。
3. **统一 API 契约保护**
   - 一份契约声明所有接口，界面、工具、worker 分发全部从它派生。
   - 禁止三处手写同一份清单（必然漂移）；禁止声明了却不暴露（不可达的僵尸接口）。
4. **结构守卫用例**
   - 把「某类 bug 曾发生过」固化成断言。例如：SQL 引用的列名必须在真实迁移里存在；
     契约里的每条路由必须在分发处有实现。

## 二、门禁（Gate G2 可编译）

全部成立才可把交付物交给 FDSE：

| 判据 | 要求 |
|---|---|
| typecheck | `pnpm -r typecheck` **0 报错** |
| 静态守卫 | 守卫用例**全绿** |
| 契约一致 | 契约声明与分发实现**逐条对应** |
| 依赖方向 | 模块边界扫描通过，无倒挂 |

**任一红即不得进入下一角色**；不得以「就这一条后面修」放行。

## 三、自查脚本

```bash
# 1. 全仓类型门禁
pnpm -r typecheck

# 2. 模块边界方向扫描
pnpm exec node scripts/check-module-boundaries.mjs

# 3. 契约与实现漂移检查（守卫用例）
pnpm exec vitest run --root server -t "contract"
```

判据：任一命令非零退出即红；typecheck 不允许 `--noEmit` 之外的降级手段绕过。

## 四、必交付物

1. **typecheck 输出**：完整命令与结果（0 报错）。
2. **守卫用例清单**：每条守卫防的是哪类历史 bug，断言写在哪。
3. **契约与实现映射表**：契约条目 → 分发点，逐条对应。
4. **依赖方向说明**：新增/改动的跨包引用走了哪个声明入口。

## 五、反例（发现即阻断）

1. **宽松类型** —— 为了让编译通过把枚举降级成 `string`、把必填改成可选，
   等于拆掉门禁换一次绿灯。
2. **契约多处手写** —— 同一份接口清单在多个文件各写一遍，某次改动静默漂移。
3. **依赖倒挂** —— 核心层反向 import 宿主 / UI，边界靠「大家都知道别这么干」维持。
4. **僵尸接口** —— 契约里声明了路由，分发处没有实现，调用即 404。
5. **守卫只覆盖 happy path** —— 守卫用例本身只测正常路径，等于没有守卫。
6. **绕过全量门禁** —— 只跑单包 typecheck 就宣称「全仓绿」。
