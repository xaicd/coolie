# wave186 — App 端网络感知 (NetInfo 缺)

> **日期:** 2026-09-30
> **触发:** 老板实测 — App 不感知网络断, 关 WiFi/飞行模式后所有操作静默失败 (没有错误回执, 用户不知道「是没反应」还是「网断了」)。
> **范围:** `clients/expo/App.tsx` (新装 NetInfo 监听) + `clients/expo/src/network.ts` (新) + `clients/expo/package.json` (加 @react-native-community/netinfo) + `clients/expo/CHANGELOG.md` (v0.6.12 条目)
> **不动:** server、db、ui (web)、任何业务屏的离线/在线逻辑

---

## 0. 一句话

App 端缺少网络断开感知。现状: 关 WiFi/飞行模式后所有 fetch 静默失败, 用户看到「点了没反应」/红屏 ErrorBoundary, 无法区分「网真断了」还是「服务端崩了」。修法: 装 `@react-native-community/netinfo` (RN 0.76.5 已把 NetInfo 从 core 抽出, expo SDK 52 默认自带 11.4.1 但项目没装), 在 `App.tsx` 顶层 `AppRoot` 挂监听, 网络从有→无时弹 Toast「网络已断开, 操作可能失败」, 网络从无→有时弹 Toast「网络已恢复」。

---

## 1. 真因

老板反复反馈「App 不感知网络断」:

| 路径 | 现状 | 问题 |
|---|---|---|
| 任何 fetch 失败 (登录、加载任务、OTA 检查等) | 走 ErrorBoundary 红屏兜底 / 屏内红字 | 用户看不出是「网断了」还是「server 崩了」 |
| 关 WiFi/飞行模式后操作 | 所有请求静默超时 | 没有主动告知, 用户以为「点了没反应」 |
| 网络恢复后操作 | 继续超时/失败 (直到下次操作) | 用户不知道可以重新试了 |

老板的「App 要感知网络断」明确要求: 网络断要主动告知用户, 网络恢复也要告知用户。

---

## 2. 设计

#### 2.1 用 `@react-native-community/netinfo` 11.4.1 (expo SDK 52 bundled)

RN 0.74 起 NetInfo 从 core 抽出, 必须显式装 `@react-native-community/netinfo`。Expo SDK 52 的 `bundledNativeModules.json` 已列 11.4.1, 项目可以直接装。

**为什么不引外部库 (如 `react-native-offline`)?** 同 wave184 Toast 的考量: 自己写一个 hook 仅 30 行, 配色/动画/语义跟 Toast 系统对齐, 第三方库做不到。NetInfo 11.x 已经是行业标准, 必须用 (自己写不出来网络事件)。

#### 2.2 网络状态变化 → Toast

- 有→无: 弹 `info` Toast「网络已断开」, 停留 3s, 不抢用户操作焦点
- 无→有: 弹 `info` Toast「网络已恢复」, 停留 3s
- 启动时已是断网状态: 不弹 (用户还没开始操作, 没必要打断) — 后续用户操作失败时已经有 ErrorBoundary/红字兜底
- 启动时已是有网: 不弹

#### 2.3 监听位置: `AppRoot` 顶层 useEffect

跟 `setupOTAListener` 同款位置 — `App.tsx` L388 的 useEffect 里挂监听, cleanup 卸载。监听器内部通过 ref 标记当前状态, 状态变化时调 `showInfoToast`。

#### 2.4 网络状态 hook

`src/network.ts` (新):
- `useNetworkStatus()` hook: 返回 `{ isConnected: boolean, isInternetReachable: boolean | null }`
- `setupNetworkListener()` 函数: 注册 NetInfo 监听器, 网络变化时弹 Toast, 返回 cleanup
- `getInitialNetworkStatus()`: 启动时取一次当前状态 (用 `NetInfo.fetch()`), 给 `useNetworkStatus` 初始值

### B. `clients/expo/src/network.ts` (新)

```ts
import { useEffect, useState } from "react";
import NetInfo, { type NetInfoState } from "@react-native-community/netinfo";
import { showInfoToast } from "./ui/toast";

export interface NetworkStatus {
  isConnected: boolean;
  isInternetReachable: boolean | null;
}

/**
 * wave186 — App 端网络感知。
 *
 * 启动时取一次 NetInfo.fetch() 作为初值, 之后 useEffect 监听事件更新。
 * 返回值用于屏内判断 (「断网时禁用按钮」等, 本期不实现)。
 */
export function useNetworkStatus(): NetworkStatus {
  const [status, setStatus] = useState<NetworkStatus>({
    isConnected: true, // 默认乐观, 第一次 fetch 回来再覆盖
    isInternetReachable: null,
  });

  useEffect(() => {
    let cancelled = false;
    void NetInfo.fetch().then((info) => {
      if (cancelled) return;
      setStatus({
        isConnected: info.isConnected ?? false,
        isInternetReachable: info.isInternetReachable,
      });
    });
    const unsub = NetInfo.addEventListener((info: NetInfoState) => {
      setStatus({
        isConnected: info.isConnected ?? false,
        isInternetReachable: info.isInternetReachable,
      });
    });
    return () => {
      cancelled = true;
      unsub();
    };
  }, []);

  return status;
}

/**
 * 注册全局网络变化监听器, 网络状态变化时弹 Toast。
 * 启动时已是断网 → 不弹 (用户还没开始操作)。
 * 有→无: 「网络已断开」info 3s。
 * 无→有: 「网络已恢复」info 3s。
 */
export function setupNetworkListener(): () => void {
  let lastConnected: boolean | null = null;

  // 启动时取一次当前状态作为基线
  void NetInfo.fetch().then((info) => {
    lastConnected = info.isConnected ?? false;
  });

  const unsub = NetInfo.addEventListener((info: NetInfoState) => {
    const connected = info.isConnected ?? false;
    // 启动期还没拉到基线 → 不弹
    if (lastConnected === null) {
      lastConnected = connected;
      return;
    }
    if (connected === lastConnected) return;
    lastConnected = connected;
    if (connected) {
      showInfoToast("网络已恢复");
    } else {
      showInfoToast("网络已断开", "操作可能失败, 请检查网络连接");
    }
  });

  return () => unsub();
}
```

## 4. 真因解释

老板 brief 写「NetInfo 缺」 — RN 0.74+ 把 NetInfo 从 core 抽出, 移到 `@react-native-community/netinfo`。Expo SDK 52 默认 bundled 11.4.1, 项目 package.json 没装, 所以 `import NetInfo from 'react-native'` 抛 `NetInfo has been removed from React Native` (实测, 见 `node_modules/react-native/index.js:454-464`)。

## 6. 发版

`scripts/release-app.sh` 走历史成熟链路:

1. bump package.json / app.json / versionCode (脚本自动)
2. `pnpm -C clients/expo typecheck` 护栏
3. `pnpm -C clients/expo bundle` 出 bundle (NetInfo native 模块需 prebuild)
4. `cd android && ./gradlew assembleRelease` 出 APK
5. coscli 上传到 xrobinai.cn
6. version.json scp 到 prod
7. publish-ota.sh 发 OTA bundle
8. 4 护栏 (version.json / ota/manifest / APK HEAD / /api/health)

> ⚠️ NetInfo 是 native module, **OTA 只换 JS bundle 不换原生**, 严格说需要出新 APK 才能跑 (同 wave213 的 Gesture handler 问题)。但 expo SDK 52 的 `bundledNativeModules.json` 已声明 11.4.1, **expo prebuild 会把它注册进 APK 的 native 层** — 也就是说, 只要新 APK 包含该 native 模块, 后续 OTA bundle 才能用。0.6.11 APK 是 wave185 出的, 不含 netinfo native 注册。所以本波必须**新出 APK**, 不能只发 OTA。

- **不动**: 任何业务屏的 fetch 失败回执 (本期仅加全局网络变化 Toast, 不改各屏错误处理)

- **遗留**: `useNetworkStatus` 的 isInternetReachable 区分「连接但无 internet」vs「完全断网」(本期只关心 isConnected)
