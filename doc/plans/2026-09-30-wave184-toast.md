# wave184 — App 端 Toast 通知系统 (失败/成功用户反馈)

> **日期:** 2026-09-30
> **触发:** 老板实测 — 登录失败/任务创建成功/清理缓存等关键操作没有用户反馈, 用户无法判断是「没反应」还是「成功」。
> **范围:** `clients/expo/src/ui/toast.ts` (重写) + `clients/expo/src/components/ToastHost.tsx` (新) + `clients/expo/src/stores/toast.ts` (新) + `clients/expo/App.tsx` (装 ToastRoot + 关键操作加 Toast)
> **不动:** 任何业务逻辑、server、db、ui (web)

---

## 0. 一句话

App 端缺少统一的轻量 Toast 通知。现状: 关键操作要么弹 `Alert.alert` 阻塞打断, 要么完全静默 (登录失败仅红字, 任务创建仅弹 `Alert.alert("任务已创建", issue.title)`, 用户体验差)。修法: 自写一个轻量 Toast 系统 (queue + Animated 滑入) — 不引外部依赖 (避免 `react-native-toast-message` 带来的 expo SDK52 兼容风险 + bundle 体积), 复用 RN 内建 `Animated` API, 配色沿用 `DESIGN.md` 的 Linear 令牌 (`C.surface` 背景 + `C.line` 边框 + 状态色左条), 在 `App.tsx` 顶层挂一个 `<ToastHost />`, 把登录失败/创建任务/退出登录/清理缓存/版本检查/草稿丢弃等关键路径的反馈全部走 Toast。

## 1. 真因

老板反复反馈「App 关键操作没反应」:

| 路径 | 现状 | 问题 |
|---|---|---|
| 登录失败 (`SignInScreen.submit`) | `setError(String(e))` 落到屏幕红色 `styles.error` 文字 | 老板实测「登录失败没看到提示」— 错误文字 + 按钮在屏底部, 容易漏看 |
| 退出登录 (`signOut`) | 完全静默, 凭证清空后直接落回登录页 | 老板实测「不知道点退出有没有用」 |
| 清理缓存 (`SettingsSheet → 清理缓存`) | `Alert.alert("缓存已清理", "释放 X")` | 阻塞打断, 跟「设置」一类静默操作气质不符 |
| 新建任务成功 (`App.tsx` onCreated) | `Alert.alert("任务已创建", issue.title)` | 阻塞打断 — 一个简单的成功回执不该抢焦点 |
| 创建任务附件失败 (CreateTaskModal L183) | `Alert.alert("附件未上传", ...)` | 同上 — 失败通知应当不打断当前操作 |
| App 检查更新 (`SettingsSheet → 版本与更新`) | `checkUpdate(true)` 调 `Alert.alert` 在 `OTA.ts:181/194` | 阻塞打断 |
| WebView 打开失败 (PipelinesScreen L63, BoardChatScreen L1252) | `Alert.alert` | 同上 |

老板的「关键操作加 Toast」明确要求: Toast ≠ Alert. Toast 不抢焦点、不打断、自动消失.

## 2. 设计

#### 1.1 复用既有抽象 `src/ui/toast.ts`

现有 `showSuccessToast(title, body?)` / `showErrorToast(title, body)` 已存在 (wave213 看板拖拽用), 但实现是包 `Alert.alert` — 这违背了「toast 不该阻塞」的语义。本次重写: 这两个函数签名不变, 实现改为入队 + 真正的 Toast UI。

#### 1.2 不引外部依赖

`react-native-toast-message` 是社区最常用的方案, 但:

- 项目 Expo SDK 52 + RN 0.76.5, 第三方库需要 expo-modules-core 0.x 兼容 (该库其实不需要 native, 是纯 JS, 但维护节奏未必跟得上)
- 加一个间接依赖 = bundle 多几十 KB (老板实测 APK 已经很大)
- 配色/动画/位置想完全跟 `DESIGN.md` 的 Linear 令牌对齐, 第三方库做不到

自己写的成本: 1 个 zustand store + 1 个 `<ToastHost>` 组件 (Animated.timing 滑入/滑出) + 1 个 `<Toast>` 子组件, 总共 ≤ 200 行, 完全可控。

#### 1.3 配色 (沿用 DESIGN.md 令牌)

- **容器**: `C.surface` 背景 (Linear surface #191A1B) + `C.line` 边框 + 圆角 10 + 左条 (4px, 状态色)
- **success** (`ok` 状态): 左条 `C.ok` (#27A644) + 图标 ✓ `Ionicons name="checkmark-circle"`
- **error** (`err` 状态): 左条 `C.err` (#EF4444) + 图标 ✗ `Ionicons name="alert-circle"`
- **info** (中性): 左条 `C.accent` (#5E6AD2) + 图标 ℹ `Ionicons name="information-circle"`
- **文字**: `C.ink` (主) + `C.ink3` (副), fontSize 13/12
- **位置**: 顶部安全区下 16px, 状态栏之下、AppBar 之上 (让 AppBar 的 OTA 更新卡不被挡)
- **停留时长**: 默认 3 秒 (信息密度低的 2 秒, 错误可点查看 5 秒), 用户可手动右滑关闭 (本期不实现, 列在遗留)

#### 1.4 Queue 模型

- store (`src/stores/toast.ts`): zustand 单例, `queue: ToastItem[]`, `enqueue(item)`, `dismiss(id)`
- ToastHost 监听 queue: 同时只显示 1 个, 多于 1 个时按 FIFO 排队, 当前 toast 自动消失后立即显示下一个
- 每条 toast 有 `id` (Date.now + counter 防同 ms 撞), `kind` (success/error/info), `title`, `body?`, `durationMs`
- 入队后 `setTimeout(dismiss, durationMs)` 自动消失; 短消息 (≤ 12 字) 2s, 长消息 3s, 错误 5s

## 3. 改动面

### A. `clients/expo/src/stores/toast.ts` (新)

```ts
import { create } from "zustand";

export type ToastKind = "success" | "error" | "info";
export interface ToastItem {
  id: number;
  kind: ToastKind;
  title: string;
  body?: string;
  durationMs: number;
}

interface ToastState {
  queue: ToastItem[];
  enqueue: (item: Omit<ToastItem, "id" | "durationMs"> & { durationMs?: number }) => number;
  dismiss: (id: number) => void;
  clear: () => void;
}

let counter = 0;

export const useToastStore = create<ToastState>((set) => ({
  queue: [],
  enqueue: (item) => {
    const id = ++counter;
    const durationMs = item.durationMs ?? (
      item.kind === "error" ? 5000 :
      item.kind === "success" ? (item.body && item.body.length > 12 ? 3000 : 2000) :
      3000
    );
    set((s) => ({ queue: [...s.queue, { ...item, id, durationMs }] }));
    return id;
  },
  dismiss: (id) => set((s) => ({ queue: s.queue.filter((t) => t.id !== id) })),
  clear: () => set({ queue: [] }),
}));
```

### C. `clients/expo/src/ui/toast.ts` (重写)

```ts
import { useToastStore } from "../stores/toast";

// 顶层 helper: 任何屏/组件都能调, 不必关心 store 实例
export function showSuccessToast(title: string, body?: string): void {
  useToastStore.getState().enqueue({ kind: "success", title, body });
}
export function showErrorToast(title: string, body: string): void {
  useToastStore.getState().enqueue({ kind: "error", title, body });
}
export function showInfoToast(title: string, body?: string): void {
  useToastStore.getState().enqueue({ kind: "info", title, body });
}
```

## 4. ToastHost 完整实现 (草稿, 见后续 diff)

关键: `useEffect` 监听 `queue[0]`, 当新 toast 出现时 `Animated.timing(slideAnim, { toValue: 0, duration: 220, useNativeDriver: true })` 滑入; `setTimeout(dismiss, duration)` 后 `Animated.timing(slideAnim, { toValue: -80, duration: 180, ... })` 滑出再 `dismiss(id)`。`useNativeDriver: true` 保证跑在原生层, 不挡 JS 线程。
