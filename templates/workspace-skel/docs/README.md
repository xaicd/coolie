# docs/ —— 本公司自己的文档目录

本目录放**这家公司（项目）自己的**设计与运维文档。基座只预置两份：

- `ARCHITECTURE.md` —— 基座架构、5 个默认模块的边界与扩展点、**按标书定制开发**指南。
- `README.md` —— 本文件，目录约定。

## 约定

- **需求**放 `../specs/`（spec workflow 的输入），**设计 / 运维** 放本目录。
- 一个主题一份文档，文件名用 `YYYY-MM-DD-<slug>.md`，便于按时间排序。
- 定制开发时新增的模块，在各模块目录内自带 `README.md`；跨模块决策写在本目录。
- 基座自带的 5 个默认模块说明在 `../modules/`，不在本目录重复。

## 建议补充的文档（按项目需要）

| 文档 | 何时写 |
|---|---|
| `ARCHITECTURE.md` | 立项时先读；架构决策变更时就地更新 |
| `DEPLOY.md` | 进入部署阶段 |
| `DATA-MODEL.md` | 领域模型定稿后 |
| `ACCEPTANCE.md` | 按标书验收前 |
