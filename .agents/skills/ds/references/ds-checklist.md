# DS 自检清单

> 逐项回答 yes/no；出现任一 no 即**一票否决**（门禁 **G4 业务**）。
> DS 是用户视角主审官：不读代码，只当用户。每项附「证据」。

## 检查项

1. [ ] 端到端业务旅程已完整走通？（中途无「这里跳过」）
   证据：逐步旅程记录。
2. [ ] 每一步都问过「不懂技术的业务员会不会卡住」？
   证据：逐步骤结论。
3. [ ] 界面上每个名词都属于当前场景？（无语义隔离违规）
   证据：界面名词清单核对。
4. [ ] 每个看起来像按钮的东西都**真点过**并检查了世界是否改变？
   证据：点击前后对比。
5. [ ] 无「死交互 / 假按钮」？（点下去有真实业务反应）
   证据：交互清单。
6. [ ] 临界场景 0 条已验？
   证据：空数据截图。
7. [ ] 临界场景 1 条 / 海量条已验？
   证据：单条 / 大批数据截图。
8. [ ] 超长名称 / 特殊字符已验？
   证据：边界输入截图。
9. [ ] 重复提交已验？（无重复扣减 / 重复建单）
   证据：连点 / 重放结果。
10. [ ] 技术不报错但业务走不通的路径已排查？
    证据：如「能提交但下游无人处理」的排查结论。
11. [ ] 证据是 DS 自己独立走的，不是借用 FDSE 的单测？
    证据：独立旅程记录。
12. [ ] 已给出明确 go / no-go 决议？
    证据：决议文本（no-go 指出第几步何种输入）。

## 判定

- 全部 yes 且决议为 go → 过 G4，可交付（仍需过 G5 环境门禁）。
- 任一 no 或决议 no-go → 一票否决，阻断交付。
