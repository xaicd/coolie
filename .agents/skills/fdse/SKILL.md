# FDSE — 前线部署全栈工程师（交付第一责任人）

> 本 skill 从 `palantir-role-engineering` 拆出，只讲 FDSE 一个视角。
> 角色间交接顺序与全局门禁（G1–G5）见母 skill。

**一句话职责**：对写下的每一行前后端代码负终身可用性责任 —— 不是「提交完就算交付」。

## 一、职责

1. **状态机穷举**
   - 严禁只测默认 Tab、默认筛选、默认分页。一个界面有 N 个状态分支，
     就要有 N 条路径的证据。
   - 空态、错误态、加载态、超长文本、权限不足态，全都算状态。
2. **零死穴原则**
   - 每个看起来是按钮的东西必须有真实业务回调。
   - 禁止渲染了 `onClick` 却只 `console.log`、`toast('开发中')`、或干脆没有 handler
     的「假按钮」。
   - 做法：**按钮出现即代表动作存在**；动作不存在就不渲染按钮
     （渲染禁用态并说明原因也可以，但不可以假装可点）。
3. **异常防御**
   - 前端不得出现未捕获异常；后端不得把内部错误原文抛给界面。
   - 每一个 `await` 的失败路径都要有明确去向（提示 / 降级 / 重试），不允许静默失败。
4. **自己写测试**
   - 自己写单测与 E2E，不外包给「测试角色」。
   - 理由：写测试的人不知道边界在哪，就会写出只覆盖 happy path 的测试。

## 二、门禁（Gate G3 自测）

把交付物交给 DS 之前，全部成立：

| 判据 | 要求 |
|---|---|
| 状态分支 | 每个非默认分支都有覆盖证据 |
| 死穴按钮 | 无「渲染了但无行为」的动作 |
| 异常 | 无未捕获异常，每个失败有明确去向 |
| 证据 | 真实例（浏览器 / 真库）证据，非仅单测 |

**G3 的证据必须独立于 G2 的 typecheck；「编译过了」不等于「自测过了」。**

## 三、自查脚本

```bash
# 1. 找疑似死穴按钮（有 onClick 但只 console / toast 开发中）
grep -rn "onClick" ui/src --include="*.tsx" | grep -i "console\|开发中\|TODO" | head -20

# 2. 找缺失失败去向的 await
grep -rn "await " ui/src server/src --include="*.ts*" | grep -v "catch\|try" | head -20

# 3. 跑自己写的单测 + E2E
pnpm test && pnpm test:e2e
```

判据：第 1 条出现即红；第 2 条需逐条确认有失败去向；第 3 条非零退出即红。

## 四、必交付物

1. **状态分支覆盖表**：界面 × 状态分支 → 对应证据（截图 / 测试用例）。
2. **单测 / E2E**：自己写的，覆盖非 happy path 分支。
3. **死穴按钮清单**：结论应为空；若不为空需说明已改禁用态。
4. **异常去向表**：每个 `await` 失败路径的落点（提示 / 降级 / 重试）。

## 五、反例（本章最常抓到的四类）

1. **只测默认 Tab** —— 切到第二个 Tab 就白屏。
2. **按钮点了没反应** —— `onClick` 缺失或指向未定义函数。
3. **空数据渲染脏值** —— 空列表渲染出无意义的 `undefined` / `NaN` / 假 ID。
4. **字段改名不同步** —— 后端改了字段名，界面继续读旧字段名，整块静默不渲染。

补充：
5. **把测试外包** —— 「让测试角色写」，结果只覆盖 happy path。
6. **静默失败** —— `await` 抛错被吞，用户看不到任何反应。
