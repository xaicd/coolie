# FDSE 自检清单

> 逐项回答 yes/no；出现任一 no 即不得过门禁 **G3（自测）**。
> G3 证据需独立于 typecheck：编译过 ≠ 自测过。每项附「证据」。

## 检查项

1. [ ] 界面每个状态分支都有覆盖证据？
   证据：空态 / 错误态 / 加载态 / 超长 / 无权限的截图或用例。
2. [ ] 非默认 Tab / 筛选 / 分页都被真实验过？
   证据：非默认分支的用例。
3. [ ] 无「假按钮」？（不存在只有 `onClick` 但无业务行为的动作）
   证据：按钮 ↔ 回调映射。
4. [ ] 每个 `await` 的失败路径都有明确去向？（提示 / 降级 / 重试）
   证据：catch / 失败分支代码行。
5. [ ] 前端无未捕获异常？（含边界输入）
   证据：控制台无错误截图。
6. [ ] 后端未把内部错误原文抛给界面？（已转译）
   证据：错误映射代码。
7. [ ] 单测 / E2E 是自己写的？（未外包）
   证据：提交记录作者。
8. [ ] 测试覆盖了非 happy path 分支？
   证据：测试用例清单。
9. [ ] 空数据不渲染 `undefined` / `NaN` / 假 ID？
   证据：空态截图。
10. [ ] 后端字段改名后界面同步？（无静默不渲染）
    证据：字段名核对。
11. [ ] 有真实例证据（真浏览器 / 真库），不只单测？
    证据：E2E 记录 / 录屏。
12. [ ] 重复提交 / 特殊字符 / 超长输入有防御？
    证据：边界输入用例。

## 判定

- 全部 yes → 过 G3，可提交 DS 做业务探路。
- 任一 no → 阻断；补齐证据后再交。
