# 课程逐字稿 → 纠错 → 教案

把一份**机器转写的课程逐字稿**变成两样东西：一份**纠错后的通顺讲义**，和一份**结构化教案**。

教案不是「讲义换个格式」，而是按教学规律重组：学习目标可观察、先纠正误解、
自测题用检索而非重读。这些原则写在 `references/pedagogy.md`。

## 适用与不适用

适用：视频/音频课程转写稿（whisper、讯飞、B 站字幕等）、讲座记录、播客文字稿。
不适用：原创写作、需要事实核查的学术引用、非课程类转写（会议纪要走别的流程）。

## 铁律（先读，违反即返工）

1. **不许编造。** 只能修字、改病句、重组顺序、加小标题。原文没讲的观点、数据、例子一个都不能加。
2. **数字必须保真。** 分数、比例、年份、名次、金额是高频错处也是高频敏感处。
   拿不准原话时保留原样并在该处标注 `【?】`，**不要猜**。
   另外：**不要统计**「某词出现几次」「共几条」这类机器视角的量——那不是讲者的内容。
3. **人名、机构名、专业名要统一。** 同一集内同一个名字只能有一种写法，见 `references/glossary.md`。
4. **保留讲者语气与口头例子。** 讲的类比、口头禅式的强调是他的教学法，
   除非明显是转写噪音，否则别删。
5. **删的是转写噪音，不是内容。** 可删：重复词、无意义填充、ASR 断句造成的破碎片。
   不可删：举例、条件限定（「某些省份」「2024 年之后」）、例外说明（「但是有个别学校…」）。

## 三步流程

### 第一步 · 清洗

去转写噪音，不动内容。能确定性做的不要交给模型（见 `scripts/clean.py`）：

- 半角标点 → 全角中文标点（`,`→`，`、`?`→`？`、`!`→`！`）
- 去掉汉字之间误插的空格
- 合并被 ASR 切开的词（「本 科」→「本科」）
- 同句内重复词去重（「这个这个专业」→「这个专业」）
- **删掉转写模型的幻觉尾句**：片尾静音段模型会编出模板化的结束语
  （实测出现过「请不吝点赞订阅转发打赏支持明镜与点点栏目」），
  那不是讲者的话，留着会让教案凭空多出一条不存在的建议。判定见 `references/glossary.md` 第六节。

### 第二步 · 纠错

逐句对照 `references/glossary.md`。glossary 没覆盖但你有把握的同音错字直接改；
**没有把握的不要改**，标注 `【?】` 让用户复核。

三类错误按优先级：

| 类型 | 例 | 处理 |
|---|---|---|
| 人名/机构/专业名 | 张雪芳 → 张雪峰 | 必须统一，见 glossary |
| 固定表述 | 证研田报 → 志愿填报 | 必须改正 |
| 同音错字 | 分呢 → 分数 | 按上下文判断，把不准标 `【?】` |

⚠️ 有一类错字要特别小心：**「考验」→「考研」、「转移」→「专业」**这类，
错的那个词本身也是合法词，盲替换会误伤。它们记在 `substitutions.json` 的
`needs_review` 里，只统计不自动改，由人工确认。

### 第三步 · 教案

按 `references/lesson-plan.md` 的结构重组，按 `references/pedagogy.md` 的原则判断。
关键顺序：

1. 先读完整篇，**列出这一讲在讲什么、分几个板块**
2. **抽误解**：讲者说「很多人以为……其实不是」的地方，就是本讲最好的教学抓手
3. 每个板块抽：**结论 / 理由 / 例子 / 例外**
4. 写**学习目标**：只用可观察动词，每条只测一件事，不含举例
5. 全局抽：关键概念、可复用的判断标准、明确说过的数字
6. 设计**自测题**：把知识点改写成闭卷能答的问句，分回忆/应用/判断三层
7. 写 2–3 个**关键问题**并注明「答到哪里算懂」

教案是**压缩**，不是改写：一讲 8000 字的逐字稿，教案应在 1500–2500 字。
宁可少写，不要注水。

## 批量处理

```bash
# 只做确定性清洗（不调模型，零幻觉风险）
python3 scripts/clean.py --input <逐字稿目录> --out <输出目录>

# 先跑一讲验收
python3 scripts/batch.py --input <目录> --out <目录> --mode both --only p2

# 全量
python3 scripts/batch.py --input <目录> --out <目录> --mode both
```

`batch.py` 可断点续跑，逐讲跑完写 `_index.md` 汇总。

**用本地小模型时必须知道的三件事**（都是实测踩出来的）：

1. **关掉 thinking。** qwen3 这类推理模型默认先输出一大段思考，
   「按规则改错字」根本不需要推理，关掉后同样任务从 6.5 tok/s → 88.5 tok/s。
2. **必须显式禁止删减。** 否则模型会把看不清的词直接删掉而不是修好
   （实测「本科证研田报」被删成「本科专业」而没改成「志愿填报」）。
3. **模型不会自己守字数上限。** 实测 6679 字的讲义能生成 12151 字的「教案」，
   比原文还长。所以有 `enforce_length` 硬门，超限自动返工压缩。

## 输出契约

```
<输出目录>/
  clean/<name>.md        纠错后的讲义（保留讲者顺序，可读）
  lesson/<name>.md       结构化教案
  _index.md              全部讲次的教案目录 + 一句话摘要
```

抬头由脚本注入（不让模型写，否则它会编日期和模型名）：

```markdown
> 来源：<原文件名>　模型：<model>　生成：<日期>
> 本稿由机器转写整理，已做错字与表达修复；未经讲者审阅。
```

## 验收清单

跑完每一讲后自查，任一项不过就重跑：

- [ ] 人名在整讲里只有一种写法
- [ ] 所有数字与原文一致（抽查 3 处）
- [ ] 没有出现原文没有的观点
- [ ] **学习目标全部用可观察动词**，无「理解/了解/掌握/熟悉」
- [ ] **每条学习目标只测一件事**，且不含「例如/比如」
- [ ] 教案长度在**上限内**（硬上限 3000、下限 1500 汉字；占比越高越正常，短讲尤其）。
      按 `[\u4e00-\u9fff]` 计，不是 `wc -m`（那个会多算三成）。详见 `references/lesson-plan.md` 的长度表
- [ ] 自测题是闭卷能答的问句，不是「本节讲了什么」
- [ ] 拿不准的地方都标了 `【?】` 而不是猜
- [ ] 中文标点全角，无半角残留

把 `【?】` 的数量报给用户——这是质量信号，不是失败。

## 已知局限

- **小模型写不出好教案。** 8B 级模型能做好「按规则改错字」，但写学习目标、
  抽误解、设计检索题这类需要判断的活，产出只能算草稿。
  要成品教案，用强模型按 `pedagogy.md` 手写。
- **学科正确性未校验。** 本流程保证「忠于原稿」，不保证原稿本身说得对。
  讲者讲错的事实，流程会忠实地保留下来。
