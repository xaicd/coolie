## 一、Web 控制台与 H5 运营端审查清单 (agent-browser)

### 1.1 页面四态穷举与状态机完备性 (Four-State Machine)
- [ ] **1.1.1 初始空态 (Empty State)**:
  - 当列表、看板、表格无数据时，严禁出现空白、错位或死报错；
  - 必须渲染友好中文空态占位图与引导提示，提供就地“新建”或“刷新”指引。
- [ ] **1.1.2 加载态 (Loading State)**:
  - 接口拉取延迟超过 100ms 时，必须具备局部骨架屏 (Skeleton) 或优雅菊花转圈；
  - 关键操作按钮在发起异步请求后，立即置灰并进入 `loading` 态，文字保持两字（如【保存】变为【保存中】或禁用），防二次重击。
- [ ] **1.1.3 成功态 (Success State)**:
  - 数据变更落地后，弹出轻量非侵入 Toast（展示时间 ≤ 2.5s），或就地局部刷新更新视图；
  - 成功反馈文案需明确具体业务实体与编号（如“工单 COOA-105 已签署”）。
- [ ] **1.1.4 异常错态 (Error State)**:
  - 网络断开、后端 500/502、或权限 403 时，展示明确的中文错误原因与【重试】两字按钮；
  - 严禁将底层未捕获的裸英文堆栈、Traceback 或 `TypeError: undefined` 直接吐给前台用户。

### 1.2 物理几何可视性与 DOM 遮挡审查 (Occlusion & Visibility)
- [ ] **1.2.1 真实点击面判定**:
  - `agent-browser` 严禁仅依赖 `is_visible()`（元素在 DOM 树中且非 `display:none` 并不代表真实可点）；
  - 必须计算目标元素与视口顶层重叠元素的 `document.elementFromPoint(x, y)`；若返回的是覆盖层浮窗、Fixed 底栏、半透明蒙层或未隐藏的加载阴影，判为 **P0 物理遮挡缺陷**。
- [ ] **1.2.2 底部与头部固定条避让**:
  - 滚动列表最下方内容是否被 Fixed 底部导航栏或操作栏遮挡；
  - 容器必须配置足够的 `padding-bottom` (至少等于底栏高度 + 16px) 确保最后一条记录完全可达。
- [ ] **1.2.3 触摸目标尺寸与间隔 (A11y Touch Target)**:
  - 核心操作按钮的可触控区域必须 ≥ 40×40px；
  - 相邻操作按钮间距 ≥ 8px，防止误触。

### 1.3 交互真实性与防假按钮打假 (Anti-Fake Interactions)
- [ ] **1.3.1 零死穴按钮 (No Dead-End Action)**:
  - 页面上所有看起来像按钮、超链接、Icon 操作点的元素，点击后必须产生确定性的行为（打开弹窗、流转状态、切换路由、展开详情或明确 Toast）；
  - 严禁存在仅绑了空 `onClick={() => {}}` 或悬空不生效的“死假按钮”。
- [ ] **1.3.2 幂等防重与表单重复提交防御**:
  - 连续以 < 300ms 间隔快速双击提交按钮，系统底层必须通过防抖或唯一 `clientRequestId` 保证只落地单次业务事务，严禁生成重复单据。
- [ ] **1.3.3 跨企业多租户物理隔离**:
  - 切换 Company 或 Project 作用域时，所有数据表格与下拉框必须原子清空并重新拉取目标上下文；
  - 绝对杜绝前一租户的残余实体闪烁或缓存泄露。

## 二、移动原生端与小程序审查清单 (agent-device)

### 2.1 6 寸屏经典布局与局部一跳 (Mobile Ergonomics)
- [ ] **2.1.1 黄金五槽位对称底栏**:
  - 移动端底栏固定且严格保持 5 个功能槽位对称布局；
  - 严禁在页面滚动时发生底栏晃动、跳帧或遮挡内容。
- [ ] **2.1.2 极简两字按钮规范**:
  - 移动端操作按钮文案必须极度凝练，默认严格收敛为**两个汉字**（如：【新建】、【保存】、【流转】、【审批】、【驳回】、【刷新】、【取消】）；
  - 详情页头部返回按钮固定为【‹ 返回】。
- [ ] **2.1.3 局部一跳因果卡片流 (Single-Hop Drawer Navigation)**:
  - 点击任务、实体、告警时，默认采用局部就地抽屉或卡片覆盖展开；
  - 严禁盲目发生整屏跨 Tab 乱跳导致调用方上下文丢失。

### 2.2 移动端物理环境与原生交互防御
- [ ] **2.2.1 软键盘弹出避让 (Keyboard Avoiding)**:
  - 在移动端表单中点击输入框呼出软键盘后，表单必须自适应向上滚动；
  - 当前聚焦输入框与【提交】按钮必须完整暴露在键盘上方，严禁输入法挡住输入内容或确认键。
- [ ] **2.2.2 系统安全区适配 (Safe Area Insets)**:
  - iPhone 灵动岛/刘海屏及底部 Home Indicator 区域必须正确应用 SafeAreaPadding；
  - 顶栏与底栏不得被硬件切角遮挡文字或点击区域。
- [ ] **2.2.3 下拉刷新与长列表性能 (Pull-to-Refresh & Virtualization)**:
  - 空态与短内容场景下，手势下拉依然必须能触发 `RefreshControl`（容器设置 `flexGrow: 1`）；
  - 长列表滚动流畅，无内存泄漏与白屏瓦片化。

### 2.3 版本决策与 OTA 静默热更守卫 (OTA Consistency)
- [ ] **2.3.1 7 处版本号强一致性**:
  - app.json、package.json、build.gradle、CHANGELOG.md、version.json、manifest、git tag 版本号源 100% 对齐。
- [ ] **2.3.2 原生 versionCode 绝对优先**:
  - 本地已安装 APK/App 的 versionCode ≥ 线上版本时，绝对禁止弹出全量安装包升级弹窗；
  - 支持 OTA 增量热更新时，优先执行静默后台拉取，重启时仅提供两字【稍后】与【重启】选项，禁止死循环弹窗打扰。

## 三、长效常态化运营与巡检清单 (Operations Patrol)

### 3.1 每日业务主旅程健康拨测 (Health Journey Probes)
- [ ] **3.1.1 登录与权限探针**:
  - 模拟管理员、前线员工与普通用户分别登录，验证 Token 签发与权限路由可用性。
- [ ] **3.1.2 商业中台履约主线巡检**:
  - 自动化端到端走完关键业务闭环（如：房源检索 → 预约带看 → 签署租约 → 押金冻结；家政服务下单 → 派单履约 → 核销码核验）；
  - 验证全流程数据库记录物理落盘一致，轧差差异率为 0。
- [ ] **3.1.3 审批流与收件箱督办**:
  - 模拟提交高危变更（特批门禁豁免、资金提额、角色指派）；
  - 验证掌柜与总监收件箱在 3 秒内收到审批卡片，点击【同意】后状态机原子扭转。

### 3.2 架构与门禁越界自动治理 (Governance Guard)
- [ ] **3.2.1 门禁越界巡查**:
  - 自动巡检全量未结项工单，检查是否有未挂载实质性工程工件而擅自扭转为 `done` 的工单（执行 No Artifact, No Done 硬拦截）；
  - 自动抓取不符合 EARS 语法的需求规格，并向 PM 发送整改提醒。
- [ ] **3.2.2 活体本体孤立实体扫描**:
  - 每日定时调用 `/api/companies/:cid/ontology/levels`；
  - 检查是否存在 `edgeCount == 0` 的孤立死实体或缺失业务动词映射的 ObjectType，自动生成治理工单。
- [ ] **3.2.3 依赖拓扑影子调用打假**:
  - 结合三态活拓扑探针，自动比对设计态依赖与运行态实际连接；
  - 发现业务微服务擅自直连其他微服务数据库（影子调用）时，自动报警并触发降级熔断。

## 四、判定准则与缺陷等级评定 (Defect Severity Matrix)

| 缺陷等级 | 现象特征 | 门禁处置措施 | 处理时效 |
| :--- | :--- | :--- | :--- |
| **Blocker (阻断级)** | • 页面白屏、崩溃闪退<br>• 核心业务主流程中断无法继续<br>• 物理遮挡导致核心提交按钮无法点击<br>• 真实资金或状态数据丢失破坏 | **一票否决**<br>立即阻断 G4/G5 门禁准出，停止生产发版，触发秒级回滚 | ≤ 1 小时 |
| **Critical (严重级)** | • 按钮无响应、出现“假死”<br>• 软键盘遮挡输入或确认键<br>• 跨企业/租户数据穿透或隔离失效<br>• 报错裸露英文底层异常堆栈 | **阻断验收**<br>必须在本轮交付迭代内修复并通过自动化回归方可准出 | ≤ 4 小时 |
| **Major (一般级)** | • 状态机四态缺失（缺少空态图或骨架屏）<br>• 按钮文案超出两字规范<br>• 移动端非对称底栏或跨 Tab 乱跳<br>• 弱网环境下重试体验不良 | **限期整改**<br>记录进缺陷台账，纳进下一发布周期基线 | ≤ 24 小时 |
| **Minor (轻微级)** | • 颜色轻微色差、间距未严格对齐<br>• 动画过渡不够平滑 | **持续优化**<br>记录进优化清单，低优先级排期处理 | ≤ 7 天 |

> [!CAUTION]
> **绝对造假红线 (Zero Tolerance on Fabricated Tests)**：
> 凡未真实拉起模拟器/真机、未真实启动无头浏览器，仅通过写死 mock 或 `expect(true).toBe(true)` 伪造通过者，一律判定为违规假交付，门禁成绩直接作废！
