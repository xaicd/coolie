## 一、Web 控制台与 H5 运营端审查清单 (agent-browser)

### 1.1 页面四态穷举与状态机完备性 (Four-State Machine)
- [ ] **1.1.1 初始空态 (Empty State)**:
  - 当列表、看板、表格无数据时，严禁出现空白、错位或死报错；
  - 必须渲染友好中文空态占位图与引导提示，提供就地“新建”或“刷新”指引。
- [ ] **1.1.2 加载态 (Loading State)**:
  - 接口拉取延迟超过 100ms 时，必须具备局部骨架屏 (Skeleton) 或优雅菊花转圈；
  - 关键操作按钮在发起异步请求后，立即置灰并进入 `loading` 态，文字保持两字（如【保存】变为【保存中】或禁用），防二次重击。
- [ ] **1.1.3 成功态 (Success State)**:
  - 数据变更落地后，弹出轻量非侵入 Toast（展示时间 ≤ 2.5s），或就地局部刷新更新视图；
  - 成功反馈文案需明确具体业务实体与编号（如“工单 COOA-105 已签署”）。
- [ ] **1.1.4 异常错态 (Error State)**:
  - 网络断开、后端 500/502、或权限 403 时，展示明确的中文错误原因与【重试】两字按钮；
  - 严禁将底层未捕获的裸英文堆栈、Traceback 或 `TypeError: undefined` 直接吐给前台用户。

### 1.2 物理几何可视性与 DOM 遮挡审查 (Occlusion & Visibility)
- [ ] **1.2.1 真实点击面判定**:
  - `agent-browser` 严禁仅依赖 `is_visible()`（元素在 DOM 树中且非 `display:none` 并不代表真实可点）；
  - 必须计算目标元素与视口顶层重叠元素的 `document.elementFromPoint(x, y)`；若返回的是覆盖层浮窗、Fixed 底栏、半透明蒙层或未隐藏的加载阴影，判为 **P0 物理遮挡缺陷**。
- [ ] **1.2.2 底部与头部固定条避让**:
  - 滚动列表最下方内容是否被 Fixed 底部导航栏或操作栏遮挡；
  - 容器必须配置足够的 `padding-bottom` (至少等于底栏高度 + 16px) 确保最后一条记录完全可达。
- [ ] **1.2.3 触摸目标尺寸与间隔 (A11y Touch Target)**:
  - 核心操作按钮的可触控区域必须 ≥ 40×40px；
  - 相邻操作按钮间距 ≥ 8px，防止误触。

### 1.3 交互真实性与防假按钮打假 (Anti-Fake Interactions)
- [ ] **1.3.1 零死穴按钮 (No Dead-End Action)**:
  - 页面上所有看起来像按钮、超链接、Icon 操作点的元素，点击后必须产生确定性的行为（打开弹窗、流转状态、切换路由、展开详情或明确 Toast）；
  - 严禁存在仅绑了空 `onClick={() => {}}` 或悬空不生效的“死假按钮”。
- [ ] **1.3.2 幂等防重与表单重复提交防御**:
  - 连续以 < 300ms 间隔快速双击提交按钮，系统底层必须通过防抖或唯一 `clientRequestId` 保证只落地单次业务事务，严禁生成重复单据。
- [ ] **1.3.3 跨企业多租户物理隔离**:
  - 切换 Company 或 Project 作用域时，所有数据表格与下拉框必须原子清空并重新拉取目标上下文；
  - 绝对杜绝前一租户的残余实体闪烁或缓存泄露。

### 2.2 8 大像素级硬核物理防御维度 (8 Physical Defense Dimensions)

- [ ] **2.2.1 6 寸极限视口防撑爆 (320px~360px Viewport Guard)**:
  - 在 `320px` 物理视口下进行拉伸测试，全站 26 个页面严禁出现意外的横向水平滚动条；
  - 任务标题、数字员工名称、状态徽标强制使用 `flexWrap: "wrap"` 与 `ellipsizeMode="tail"` 保护，严禁内容相互叠字或溢出屏幕边缘；
  - 属性抽屉右侧属性列在窄屏下自动下沉或自适应折行。

- [ ] **2.2.2 系统安全区防遮挡 (Safe Area Insets & Dynamic Island)**:
  - 适配 iPhone 灵动岛、刘海屏切角以及 Android 顶部打孔屏，顶栏标题与返回按钮内边距留足（≥ 44px）；
  - 底部适配 Home Indicator（小白条），列表与可滚动容器底边留足 `paddingBottom: insets.bottom + 16px`，确保最后一行卡片或操作按钮完全露头且可点。

- [ ] **2.2.3 软键盘贴合与视口避让 (Keyboard Avoiding & Sticky Actions)**:
  - 在工单会话（`TaskDetailScreen`）、工坊聊天（`BoardChatScreen`）或表单输入页点击文本框弹起软键盘时：
    - 输入框必须贴合在软键盘正上方（零重叠遮挡、零异常闪烁）；
    - 【发送】或【保存】按钮必须完整暴露在键盘上方，绝对禁止输入法弹起后遮挡操作键；
    - 外部区域点击或向下滑动手势必须能顺畅收起键盘（`Keyboard.dismiss()`）。

- [ ] **2.2.4 LIFO 物理导航栈与返回键防误退 (Hardware Back & LIFO Stack)**:
  - 在 Android 真实设备或模拟器上按硬件物理返回键（Back）：
    - 若当前有 Modal、抽屉（Sheet）或下拉浮层处于展开态，**必须且仅能关闭当前顶层抽屉**，严禁直接退出 App；
    - 若在二级/三级页面，必须逐级返回上一级页面并保持上一页的滚动位置与过滤条件，严禁跳回顶部或跨 Tab 错位；
    - 仅在主页顶层（5 大 Tab）按返回键时，允许弹出两字确认【退出】或双击退出。

- [ ] **2.2.5 极简两字规范与零死穴交互 (Two-Word Minimalist & Anti-Dead-End)**:
  - 全站所有操作按钮文案 100% 收敛为**两个汉字**（如：【新建】、【保存】、【审批】、【驳回】、【发送】、【停止】、【刷新】、【撤回】、【流转】）；
  - 详情页返回按键固定为【‹ 返回】；
  - 页面上每一个按钮必须绑定真实的确定性逻辑，点击后必须产生网络请求、UI 状态迁移或弹层反馈，绝对杜绝空 `onPress` 死穴按键。

- [ ] **2.2.6 离线弱网与断网降级韧性 (Network Resilience & Graceful Fallback)**:
  - 模拟飞行模式或拔掉网线时：
    - 页面严禁出现白屏瓦片化、红屏崩溃或裸英文 `Network Error` / `ECONNREFUSED`；
    - 必须就地渲染中文化离线卡片，显示明确的插头断网图标与【重试】两字按钮；
    - 重新连网后点击【重试】，界面必须无缝自动恢复最新数据。

- [ ] **2.2.7 活体本体与实体动词抽屉 (Living Ontology Mobile Interaction)**:
  - 进入项目后自动关联专属本体域，实体卡片必须展示孪生属性与因果血缘；
  - 点击实体卡片必须就地弹出受控动词操作抽屉（Action Drawer），严禁静态只读展示死报表；
  - 触发动词操作后，状态立即本地预测流转并回读数据库确认。

- [ ] **2.2.8 交付工件就地查验与真机快照总线 (Artifact Preview & No Done without WorkProduct)**:
  - 任务详情中挂载的工件（Work Products）必须在手机端支持直接点击查验：
    - 截图与图片支持点击查看大图与捏合手势缩放；
    - 架构图、代码 Diff 支持行内高亮查阅；
    - 网页与报告支持就地内嵌 WebContainer 预览；
  - **严禁“0 件挂 workProduct”假完工**：任何标为 `done` 的工单必须附带至少一项移动端真机可查验工件凭证。

### 2.3 5 大核心商业交付旅程端到端闭环 (Five End-to-End Business Journeys)

走查人员必须手持真机，完整跑通以下 5 条端到端闭环旅程，有一处断点即判定不合格：

- [ ] **旅程一：掌柜一句话意图派单全闭环 (Voice/Text Intent to Task)**:
  - 手机端打开工坊 ➜ 语音/输入框输入一句话意图（如“把工单属性栏改成两字”） ➜ 系统 1500ms 动态防抖补全 ➜ 自动生成结构化任务卡片 ➜ 点击两字【派单】 ➜ 控制面生成物理工单并在任务 Tab 可查。
- [ ] **旅程二：高危变更与审批单手机端原子签署 (Mobile Approval Gate)**:
  - 系统触发高危变更或特批（如资金提额、门禁豁免） ➜ 掌柜手机端收件箱在 3 秒内收到审批卡片 ➜ 点击卡片查阅不可变证据与影响面 ➜ 点击两字【同意】或【驳回】 ➜ 控制面状态机原子扭转且不可篡改。
- [ ] **旅程三：人机工坊沉浸式交互与流式打字机 (Foundry Chat Stream)**:
  - 手机端向 Hermes 发送长文本或代码片段 ➜ 接收流式打字机分块渲染 ➜ 滚动条自动吸底跟随 ➜ 点击代码块右上角两字【复制】有 Toast 反馈 ➜ 会话断开具备自动重连。
- [ ] **旅程四：活体本体穿透与动词执行 (Living Ontology Navigation)**:
  - 打开资产 Tab ➜ 进入项目本体域 ➜ 展开业务实体卡片 ➜ 查看关联的 WBS 任务与代码 Commit 血缘 ➜ 点击动词执行操作 ➜ 观察数据库状态物理同步。
- [ ] **旅程五：终验核销与可验证工程资产归档 (UAT Sign-off & Artifact Verification)**:
  - 检视最终工单交付物 ➜ 在手机端查阅端到端四态真机快照、OpenAPI 契约与回滚 SOP ➜ 确认无误后签署《客户终验单》 ➜ 归档结项。

## 三、长效常态化运营与巡检清单 (Operations Patrol)

### 3.1 每日业务主旅程健康拨测 (Health Journey Probes)
- [ ] **3.1.1 登录与权限探针**:
  - 模拟管理员、前线员工与普通用户分别登录，验证 Token 签发与权限路由可用性。
- [ ] **3.1.2 商业中台履约主线巡检**:
  - 自动化端到端走完关键业务闭环（如：房源检索 → 预约带看 → 签署租约 → 押金冻结；家政服务下单 → 派单履约 → 核销码核验）；
  - 验证全流程数据库记录物理落盘一致，轧差差异率为 0。
- [ ] **3.1.3 审批流与收件箱督办**:
  - 模拟提交高危变更（特批门禁豁免、资金提额、角色指派）；
  - 验证掌柜与总监收件箱在 3 秒内收到审批卡片，点击【同意】后状态机原子扭转。

### 3.2 架构与门禁越界自动治理 (Governance Guard)
- [ ] **3.2.1 门禁越界巡查**:
  - 自动巡检全量未结项工单，检查是否有未挂载实质性工程工件而擅自扭转为 `done` 的工单（执行 No Artifact, No Done 硬拦截）；
  - 自动抓取不符合 EARS 语法的需求规格，并向 PM 发送整改提醒。
- [ ] **3.2.2 活体本体孤立实体扫描**:
  - 每日定时调用 `/api/companies/:cid/ontology/levels`；
  - 检查是否存在 `edgeCount == 0` 的孤立死实体或缺失业务动词映射的 ObjectType，自动生成治理工单。
- [ ] **3.2.3 依赖拓扑影子调用打假**:
  - 结合三态活拓扑探针，自动比对设计态依赖与运行态实际连接；
  - 发现业务微服务擅自直连其他微服务数据库（影子调用）时，自动报警并触发降级熔断。

## 四、判定准则与缺陷等级评定 (Defect Severity Matrix)

| 缺陷等级 | 现象特征 | 门禁处置措施 | 处理时效 |
