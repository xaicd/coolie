# ADR-002: 单人原子签出锁 (Single-Assignee Task Checkout) 与预算硬停自动熔断机制

- **状态**: 已接受 (Accepted)
- **决策人**: Hermes (PM 掌柜), 铁匠 (Core-SWE), 墨斗 (前线架构师 FDA)
- **决策日期**: 2026-10-03
- **归属规范**: CMMI 03_design (TS) / .agents/skills/adr-architect

---

## 1. 背景与问题陈述 (Context and Problem Statement)
在全自主数字员工团队协同中，存在两大毁灭性风险：
1. **并发代码踩踏**：多个智能体并发领任务或并发修改同一模块，由于缺乏排他性锁，导致代码相互覆盖、Git 分支分叉与死循环冲突；
2. **Token 账单失控**：智能体若遭遇死循环调用或幻觉失控，能在数分钟内消耗海量 API 额度，造成无法挽回的财务灾难。

---

## 2. 考虑的候选方案 (Considered Options)
- **方案 A (采纳)**: **控制面单人原子签出锁 + 租期心跳续期 + 实时预算硬停熔断**。
- **方案 B**: 乐观锁版本号控制（由 Git rebase 冲突在最后提交阶段由人工解决）。
- **方案 C**: 软性配额告警（仅发通知，不阻断执行）。

---

## 3. 决策结果 (Decision Outcome)
**选用方案 A**。
- **原子签出**: 工单执行前必须调用 `POST /api/issues/:id/checkout` 成功抢占锁；同一时刻单一工单仅允许单一负责人，非持有者写操作一律返回 `409 Conflict`；
- **租期保护**: 智能体定期发送心跳续约，心跳丢失超时 900s 后自动释放锁（僵尸锁回收）；
- **预算硬停**: 服务端 `costs.ts` 实时累计智能体 Token 费用，触及公司/智能体预算上限时，立即阻断签出锁并强制将智能体状态变更为 `paused`，同时向掌柜推送 🔔 审批提额卡片。

---

## 4. 后果与权衡 (Consequences)
- **积极影响**:
  - 从物理上根绝了多智能体并发抢占任务与踩踏修改同一文件的可能；
  - 兜底了财务风险，任何超预算行为在 1 秒内被物理掐断。
