# ADR-003: 家政履约状态机、分布式事务补偿与双向对账守恒断言

- **状态**: 已接受 (Accepted)
- **决策者**: 墨斗 (前线架构师 FDA · modou-fda)
- **日期**: 2026-10-10
- **关联门禁**: G2 架构与事务守恒门禁 (`gate_g2_arch`)

---

## 1. 上下文与问题陈述 (Context)
家政服务订单履约涵盖“居民下单 -> 微信支付 -> 服务商派工 -> 技工上门签到/签退 -> 评价/退款 -> 结算”全链路。涉及微信支付回调网络抖动、技工迟到超时自动退款、多节点并发派工冲突等问题，必须确立严谨的状态机模型与账实守恒机制。

## 2. 决策驱动力 (Decision Drivers)
1. **资金不可篡改与账实守恒**: 支付流水、订单实收、退款出金、服务商结算必须双向平衡，严禁单边账；
2. **状态跃迁不可逆**: 订单状态跃迁严格单向递进，防止非法反向流转；
3. **并发防重复派工/核销**: 分布式并发环境下，同一订单严禁被两个节点同时派工。

## 3. 考虑的备选方案 (Considered Options)
1. 方案 A: 纯依赖数据库乐观锁 `version` 字段
2. 方案 B: Redisson 分布式锁 + 严格状态机跃迁模型 + RocketMQ 延迟事务补偿 + 进出借贷对账断言
3. 方案 C: 重型分布式事务框架 (Seata AT 模式全局锁)

## 4. 决策结果 (Decision Outcome)
**选择 方案 B**。
- 写操作前获取 Redisson 分布式锁 `lock:order:{orderNo}`，租期 5 秒；
- 订单状态采用显式枚举（`UNPAID` -> `WAIT_DISPATCH` -> `DISPATCHED` -> `IN_SERVICE` -> `FINISHED`），每个跃迁方法前置断言期望状态；
- 未支付订单配置 15 分钟 RocketMQ 延迟关单；未派工订单配置 4 小时超时自动退款补偿；
- 在结算与退款 Service 中硬编码双向账实守恒数学断言：
  `Assert.isTrue(actualPaid == refundAmount + settleAmount + platformFee, "资金分账守恒破坏");`
- 每日凌晨执行 `pay_reconciliations` 日终对账汇总任务。

## 5. 预期结果与正负面影响 (Consequences)
- **正面收益**:
  - 消灭重复支付、超卖与并发派工冲突；
  - 资金链路完全闭环，满足政企审计 180 天留存合规要求。
- **负面风险与缓释**:
  - 微信 Webhook 回调失败可能导致掉单 -> 配置延迟主动查询微信支付接口机制。
