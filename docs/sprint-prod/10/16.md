## 1. 2026-10-16 今日关键原话与拍板决策 (Customer Utterances Ledger)

### 决策点 1：Mac 宿主机本地施工队定位与商业项目主客体正交隔离铁律
- **掌柜原话**:
  - *"要明确几个事 1. mac 宿主机 coolie-dev 专门用来建设 coolie工坊产品,属于本地施工团队 2. coolie工坊生产环境 主要是 原生APP在使用, residential-plan-service 只是 生产APP中的一个 项目, 跟coolie工坊产品 本身没有关系"*
- **物理真值与职责边界实勘**:
  1. **Mac 宿主机 `coolie-dev` 的绝对生态位与使命**:
     - **定位**: 工坊平台本体的“本地施工队 (Local Construction Team)”，是生产工具的制造者；
     - **职责**: 专门负责建设、迭代、打磨与发布 Coolie 工坊产品本身（控制面 REST API、原生移动 APP 客户端、Web 驾驶舱、MCP 编排中枢、CMMI 自动化守卫与发版流水线）；
     - **环境**: 依托 Mac Studio 前线驾驶舱物理硬件（独占 Android 模拟器、Xcode/iOS 模拟器、Node 24、brew 构建链），开发、验证并通过 23 项 Pre-commit 守卫后，推送到 GitHub 并持续向 `tc-coolie-claw` 生产服务器及客户端分发。
  2. **生产环境的第一交互入口是原生手机 APP**:
     - 生产环境主要面向掌柜、交付总监与前线 FDE，通过**原生手机 APP (Expo Native Mobile App)** 随时随地进行全盘态势感知、一句话意图派单、卡片式移动审批与资产检视；
     - 原生 APP 是工坊决策中枢（第一层生命周期）在移动端的最高保真投射。
  3. **商业交付项目与工坊平台的正交物理隔离 (Orthogonal Isolation)**:
     - `residential-plan-service` 仅仅是在生产环境工坊 APP 中立项孵化、协同推进的一个**外部商业交付项目 (Client Delivery Project)**；
     - 它跟 Coolie 工坊产品本身**没有任何工程或代码耦合关系**！
     - **主客体铁律**: Coolie 是“软件制造交付工厂 / 控制面母体”，`residential-plan-service` 是“工坊流水线上承接的一个垂直业务标的”；
     - 严禁将客户项目的技术选型（如空间几何计算、Node 单体脚本）与工坊平台自身的产品架构混为一谈；
     - 严禁让客户项目的业务代码反向侵入或污染工坊控制面代码库，两者严格保持物理正交与独立生命周期。


### 决策点 2：生产 APP 登录失败根因溯源与本地配置反向污染三层硬熔断守卫
- **掌柜原话**:
  - *"coolie工坊 生产APP登录不上了, 是不是 APP APK 包有问题"*
- **物理真值与缺陷根本原因实勘 (Root Cause Analysis)**:
  1. **掌柜直觉完全命中**: 生产 APP APK 包 (v0.6.58) 与线上历史 OTA 增量包确实存在致命打包缺陷，导致任何物理手机安装后均无法登录。
  2. **根因链条 (5-Whys 溯源)**:
     - **表现**: 用户在真机上输入正确邮箱与密码点击“登录”，直接弹窗报“网络连接失败，请检查网络后重试”；
     - **第一因**: 客户端发起的所有网络请求直接在 TCP/Socket 层失败，根本未能抵达生产服务器 `xrobinai.cn`；
     - **第二因**: 逆向解包 `index.android.bundle` 与 HBC 字节码发现，`COOLIE_BASE_URL` 被写死成了 `http://10.0.2.2:3100`；
     - **第三因**: `10.0.2.2` 仅为 Android 模拟器访问宿主机 loopback 的专用网关，真实物理手机根本无法路由该 IP；
     - **第四因 (致命暗洞)**: Mac 宿主机发版工作区中遗留了本地开发配置文件 `clients/expo/.env.local`，其中定义了 `EXPO_PUBLIC_COOLIE_BASE_URL=http://10.0.2.2:3100`；
     - **第五因 (制度与守卫缺失)**: `scripts/release-app.sh` 与 `publish-ota.sh` 虽然执行了 shell 变量 `unset EXPO_PUBLIC_*`，但 Expo CLI (基于 `@expo/env` / `dotenv`) 在 `expo export` 和 `assembleRelease` 时会**自动无视 shell 直接从磁盘文件加载 `.env.local`** 并内联编译进 bundle，且发版脚本缺乏针对导出 bundle 的目标地址机器校验断言！
  3. **三层高可靠防御落地实施**:
     - **物理隔离层**: `publish-ota.sh` 与 `release-app.sh` 在构建前强制自动扫描并隔离重命名 `.env.local`、`.env.development*` 等开发环境文件；
     - **构建机检硬门禁**: 在 `publish-ota.sh`（OTA 导出后）与 `release-app.sh`（APK 产物生成后）增加自动化 bundle 检查，解包扫描 `dist/` 与 APK `assets/index.android.bundle`，强制断言包含 `https://xrobinai.cn`，一旦缺失或检测到回环地址直接中断发版并回退 commit；
     - **运行时代码级防御**: 在 `clients/expo/src/instanceTarget.ts` 中引入 `__DEV__` 守卫，非开发环境下严禁使用任何 `10.0.2.2`、`localhost`、`127.0.0.1` 地址，强制回退至 `PROD_INSTANCE_BASE_URL` (`https://xrobinai.cn`)。
  4. **全链路验证闭环**:
     - 干净生产 OTA 增量包与 Manifest 已推送至生产服务器 `ubuntu@xrobinai.cn:/opt/coolie/ui/ota/`；
     - 在 Android 模拟器实测：输入邮箱密码提交登录，网络请求直连 `https://xrobinai.cn/api/auth/sign-in/email`，成功收到 401 并正确渲染“账号或密码错误”提示，彻底修复“网络连接失败”假死阻塞。

### 决策点 3：工坊对话 @ 员工智能联想与服务端直驱派单闭环
- **掌柜原话**:
  - *"coolie工坊 员工 相互之间 有审批过程吗 工坊对话 是否看得到 审批记录 或者AT"*
  - *"工坊对话 能 @ 员工吗"*
  - *"对"*
- **物理真值与设计实现实勘**:
  1. **员工分层审批机制**:
     - **法定治理级 (Human-in-the-Loop)**: 涉及资金额度 (`spend_money`)、员工雇佣 (`hire_agent`)、高危指令 (`execute_command`)，员工仅有权发起，必须由真实人类掌柜在对话卡片或待办抽屉中点击「同意/驳回」签名裁决；
     - **工程交付级 (Inter-Agent Multi-Stage Review)**: 在 CMMI 流水线上，铁匠 (SWE) 提交代码后自动转入 `in_review` 并原子移交给门神 (FDSE/QA) 审查，门神通过后推进下一步或驳回打回铁匠 (`changesRequestedCount` 累加，超过 3 轮触发防死循环熔断升级通知人类)。
  2. **移动端键盘监听 @ 浮层实装 (`ChatInput.tsx`)**:
     - 在原生 APP 聊天输入框内输入 `@` 或 `@字符` 时，输入框上方就地弹出 5 位舰队核心数字员工（⚡Hermes、📐墨斗、🔨铁匠、🛡️门神、⚓兜底渊）的候选气泡；
     - 轻点员工头像或名字，自动平滑替换为 `@员工名 `，并在插入完成后自动收起浮层，彻底补齐原生移动端缺少 @ 选人联想的缺陷。
  3. **服务端工坊对话 @ 派单直驱引擎实装 (`server/src/routes/board-chat.ts`)**:
     - 升级 `detectAndExecuteDirectAction` 意图匹配器，全面支持 `@员工名 任务内容` 与 `@员工名 在 XX分钟内 完成任务`（同时保留传统 `让/派/叫/安排` 句式）；
     - 精准排除疑问句与纯咨询句（如以？结尾，或“如何/怎么/为什么/什么是/介绍一下”等），咨询继续流转至 Hermes 会话模型回复；
     - 执行派单动作时，直接在数据库原子建单或防重对齐、锁定 AIP Bootcamp 风格 Time-Box 倒计时时间盒、向心跳队列注入即刻唤醒信号，并在会话流中秒级输出高信噪比派工卡片。
